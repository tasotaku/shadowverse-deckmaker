# 対戦AI：方式と検証

対戦ラボの「AIが一手実行」で、今の局面からAIに手を選ばせます。「自動対戦」は両者の手を同じ方式で選びます。
「AI対戦例を開く」は終局まで実行済みの記録です。一手ずつ進む・戻る・ターン移動に対応し、
右の「この手のAI判断」で理由と比較候補を確認できます。保存記録にも判断を残します。
演出OFFにすると表示待ちを省略します。

## 選んだ構成

共通の盤面評価と現在ターン内の手順探索を組み合わせます。カード名ごとの手順表は作らず、
対戦処理に合法手を実行させて、体力・盤面・能力・手札枚数・PP最大値・進化権・危険を比較します。
勝敗は通常の評価より優先します。両デッキに同じ方式を使い、デッキ別の結果も分けて測定します。

| 方式 | 役割 |
|---|---|
| 無作為 | 最低限の比較対象。合法手から選ぶ |
| 一手評価 | 1手後だけを比較する固定基準 |
| 先読みAI | 最大6手、各段階で上位6経路、最大160候補を試す |
| 調整した先読みAI | 対戦結果から11個の評価重みを変え、同じ探索量で比較する |

深いニューラルネットワークによる強化学習は今回実装していません。小さな評価式の重みを変え、
対戦で勝ちやすい候補を残す進化的な学習を実装しました。逐次LLMも呼びません。
今ある環境で高速・再現可能に比較でき、弱い判断を手順と数値で調べられる構成を選んだためです。
LLM方式や深層強化学習より強いと実験で示したわけではありません。

参考にした研究は、[Hearthstoneの評価方式を対戦から調整する研究](https://arxiv.org/abs/2410.19681)と、
[学習した盤面評価を探索に組み合わせる研究](https://arxiv.org/abs/1808.04794)です。
これらは方式選定の参考であり、本実装が論文の手法・性能を再現したという意味ではありません。

## 覗き見を防ぐ境界

`Player.choose()` に渡すのは `Battle.observation()` の出力と公開カード定義だけです。
実際の相手手札、両山札の中身・順番、内部乱数、次の個体番号は渡しません。
画面で両者の手札を表示してもAIの入力は変わりません。

探索用には枚数を維持した仮の手札・山札を作ります。公開済みカードのクラスを参考に登録カードから仮定する簡易方式で、
正確な残り枚数の推定や既使用カードの記憶は未実装です。独立した2通りの仮定を使います。
ドロー・デッキからの召喚・ランダム処理に触れたらその経路の先読みを止め、実行後の新しい観測で考え直します。
確定した勝ちとして表示するのは、未知の結果を含まない手順だけです。候補の評価値は勝率ではありません。

生成カードの番号は仮想盤面と実際の盤面で異なります。画面の対戦は毎回一手を選び直し、
`execute_plan()` は生成後の公開位置とカード種から仮番号を解決して、決定的な手順を実行します。
未知の結果を含む手順はまとめて実行せず拒否します。

## 測定方法

- 初手の引き直しは両者ともなし。登録済み2デッキの同種対戦2組と異種対戦1組で比較。
- 各開始条件でAIの先後を入れ替える。デッキ配置・初期乱数・探索上限を固定する。
- 学習は101〜112（1手評価の重み）、301〜312（先読みの重み）。評価用の乱数とは分離。
- 勝ち1点、引き分け0.5点。500操作で未終局なら別件数として記録し、勝利や引き分けに混ぜない。
- 全試合の先後・デッキ・勝敗・操作数・計算量・所要時間をJSONに保存する。
- 勝率の区間は同じ条件の先後ペアを再抽出した参考値。小標本や全勝の場合の確実性を保証しない。
- 最終評価を見て重みを再調整しない。比較相手と条件に対する相対性能であり、人間上級者との比較ではない。

## 確認済みの結果

| 比較 | 対戦数 | 勝ち | 負け | 引分・未終局 |
|---|---:|---:|---:|---:|
| 先読みAI → 一手評価 | 96 | 59 | 37 | 0 |
| 先読みAI → 無作為 | 48 | 48 | 0 | 0 |
| 調整版 → 先読みAI | 96 | 51 | 45 | 0 |
| 調整版 → 一手評価 | 48 | 28 | 20 | 0 |

先読みAIの対一手評価勝率は61.5%。同じデッキでも先読みを増やす効果が出ています。
デッキ別ではランプドラゴン28/48勝、ラストワードナイトメア31/48勝です。
この勝率をデッキそのものの対人勝率として扱うことはできません。

最初の学習は6候補×3世代×24対戦＝432対戦を実行しましたが、基準を上回る重みを選べませんでした。
改善が確認できない試行も[全履歴](evidence/ai-training.json)へ残しています。
先読みありの学習も432対戦実行しました。学習中には改善候補が見つかりましたが、
未学習条件20001〜20016では調整前に対して51勝45敗（53.1%）、ペア単位の区間は43.8〜62.5%でした。
ランプドラゴン23/48勝、ラストワードナイトメア28/48勝で、両方の改善ともいえません。
したがって**調整版を初期設定には採用していません**。選択欄の「調整版（比較用）」で利用できます。
デッキごとの別方式も、この結果だけで有利と断定できないため導入していません。
重みは[保存モデル](../src/svdeck/data/battle_ai_model.json)、
過程は[先読みの学習履歴](evidence/ai-search-training.json)、
最終比較は[調整前との比較](evidence/ai-trained-vs-search.json)・[一手評価との比較](evidence/ai-trained-vs-greedy.json)に保存しています。
学習864対戦＋独立評価288対戦＝**1,152対戦**。全て終局し、未終局0でした。

戦術課題は、直接攻撃・守護突破・小打点でバリアを剥がす・進化前後・超進化の追加打点・
回復と自傷の順序・ターン終了時の打点・捨てたときの打点・自滅するモードの回避です。
カード本文とルールから期待結果を決め、逆順など実際に負ける例も実行して検査しています。
調整前・調整後とも9課題を通過しました。情報漏洩防止、生成カード番号の解決、HTTPでのAI実行、
判断の保存再生・分岐、未終局の集計、学習モデルの識別も含むAI関連46テストがPASSです。

利用中の `http://127.0.0.1:8767/` でAIの一手実行、途中局面からの自動対戦の終局、
保存例のターン移動・判断表示を実操作で確認しました。1366×768と1100×650で画面内に操作を維持し、
独立した画像確認も4項目PASS（[通常PC](evidence/battle-ai-desktop.png)・[小さめのPC](evidence/battle-ai-small-desktop.png)）。
調整版の一手実行と、ページを再読込しても方式・判断理由が保持されることも確認しました。
配布物へAIコード・モデル・保存対戦が同梱されることを検査済みです。

## 再実行

```sh
# 一手評価の重みを学習（結果を直接採用はしない）
.venv/bin/python -m svdeck.battle_training train --output training.json --workers 4
# 同じ計算量の先読みAIを対戦で調整
.venv/bin/python -m svdeck.battle_training train --training-policy search --output search-training.json --workers 4
# 未学習条件で比較
.venv/bin/python -m svdeck.battle_training evaluate --policy search --opponent greedy --seed 10001 --seeds 16 --output evaluation.json
# 人が見返せる一試合を保存
.venv/bin/python -m svdeck.battle_training replay --policy search --opponent search --seed 24051 --output replay.json
```

`train` に `--model-output candidate.json` を加えると小さな重みファイルも保存します。
プログラムからは `Player(cards, weights=model['weights'])` でその候補を比較できます。
配布モデルを差し替える前に、別の開始条件と戦術課題で検査します。

保存したリプレイは対戦ラボの「記録を開く」で読めます。画面は通常の `svdeck-battle-web` と同じ8767番です。
`battle_ai.py` が判断、`battle_training.py` が学習・測定を担当し、効果処理や演出とは分離しています。

## 残る弱点

現在ターンを中心に限られた候補だけを探索します。相手が次に手札から使うカードを含む長期の読みは行わず、
相手の盤面から受ける危険も評価式による近似です。ドローを挟む長いコンボ、手札の温存、構築全体の勝ち筋、
初手交換の最適化は弱点として残ります。環境のルール再現に誤りがあれば、その誤りを利用するAIにもなり得ます。
今回の成績は自作環境と収録2デッキの範囲の結果です。

## プレイ指摘への修正（2026-09-14、判断方式2）

保存対戦の先攻3・4ターンと後攻5ターンを[固定した開始状態](evidence/ai-play-feedback.json)で再現しました。
旧方式は、攻撃した直後とターン終了後をそのまま比較していました。後者だけ相手の通常ドローと
最大PP増加が含まれ、後攻5ターンの指摘局面では4.3点の不利益となっていました。
ゾーイを倒せない2/1の突進攻撃が、何もせずターンを終えるより高く評価される原因の一つです。

初期設定の先読みAIは、候補を自分のターン終了後にそろえて評価します。さらに公開盤面からの攻撃・
ドレイン回復と、次の自分のターンに使える手札の最大コストを近似評価します。
相手の手札からの反撃や対面全体の長期有利はまだ読めません。カード名を条件にした指示は加えていません。

同じ局面から毎手考え直して実行すると、次を確認できました。

- 先攻3ターン：ルリアより先に竜の啓示を使い、次ターンに手札のゾーイを使える最大PPへ進める。
- 先攻4ターン：ルリアのバリアでドレイン持ちのバットを倒し、竜の啓示も使う。
- 後攻5ターン開始：ゾーイを倒し切る。全盤面を最良の手順で処理できるとまでは確認できていない。
- 後攻5ターンの突進直前：もう倒せない局面では2/1を残してターンを終了する。

この4局面を再発防止テストに追加しました。元の66操作の保存リプレイは当時の判断記録として維持します。
修正版の判断は「AIが一手実行」や新規対戦に適用されます。
利用中の8767番のAI実行入口でも4局面を最後まで実行し、[判断と終了状態](evidence/ai-feedback-v2-results.json)を保存しました。
静的型チェックとAI関連57テストはPASSです。

旧方式との独立した96戦（乱数30001〜30016、同種2組・異種1組、先後入替）は
**51勝45敗、53.1%**、参考区間46.9〜59.4%。ドラゴン28/48勝、ナイトメア23/48勝でした。
指摘局面は改善しましたが、全体の強さが向上したと断言できる結果ではありません。
[全対戦結果](evidence/ai-turn-v2-vs-v1.json)を保存しています。候補は160件までで、評価のための
ターン終了処理が追加されるため、同じ候補数でも実際の処理回数は旧方式より増えます。

再実行：`svdeck-battle-ai evaluate --policy search --opponent legacy --seed 30001 --seeds 16 --output evaluation.json`。
比較用の `legacy` と既存の配布済み調整モデルは方式1を維持します。新しく学習するモデルには学習時の方式を保存します。
