# カードアトム抽出プロンプト

LLM抽出器への指示書。入力はカード情報のJSON配列（`python -m svdeck.atoms dump` の出力）、
出力は下記スキーマのJSON配列（`python -m svdeck.atoms load` で取り込む）。
オントロジーの正本は docs/design.md §4〜6。ここは抽出器が単体で読める要約＋規約。

## 役割

Shadowverse: Worlds Beyond のカード能力テキスト（skill_text）を、機械マッチ可能な
「アトム」に分解する。**漏らすより出しすぎに倒す**（過剰抽出は人が後で削る。欠落は発見できない）。

## ルール前提（確定済み・この通りに解釈する）

| ルール | 内容 |
|---|---|
| 覚醒 | 自分のPP最大値7以上 |
| ネクロマンスN | 墓場をN**消費**する（減る） |
| 墓場カウント | フォロワー死亡・スペル使用・アミュレット破壊で+1。「墓場を+2する」は純カウンタ増 |
| 進化権/超進化権 | 先攻後攻とも各2個。進化=先攻T5/後攻T4から、超進化=先攻T7/後攻T6から |
| エクストラPP | 後攻のみ。そのターンだけPP+1。T1〜5で1回・T6以降で1回・任意タイミング |
| 進化の区別 | **【進化時】は進化権を使った進化でのみ発動**。「〜が進化したとき」は効果による進化でも発動する。効果テキストの「進化する」は進化権を消費しない自動進化 |
| 手札に加える | 「デッキから引く」と書かれた場合のみ山札から取る（山札−）。「手札に加える」は新規生成で山札は減らない |
| ゾーン | 場 / 手札 / 山札 / 墓場 の4つのみ（EXエリアは存在しない） |
| クラス | ニュートラル/エルフ/ロイヤル/ウィッチ/ドラゴン/ナイトメア/ビショップ/ネメシス。ネクロマンス等のキーワードはクラス固有 |
| マークアップ | skill_text中の `<color=Keyword>〜</color>` は公式キーワード強調、`<hr>`は能力の区切り、`<ev>〜</ev>`は進化後能力 |

## 抽出規約

1. **アトム** = `[発動要件] → 述語(対象, ゾーン, 量)`。`<hr>`区切り・文単位で分解する。
2. **発動要件は全部記録する**（ファンファーレも特別扱いしない）。トリガ（ファンファーレ/ラストワード/進化時/超進化時/攻撃時/交戦時/ターン終了時…）、リソースゲート（覚醒/ネクロマンスN/スペルブーストN/エンハンスX/コンボN/連携N…）、状態条件（場に◯◯がある…）すべて。
3. **デルタ分解**: ゾーン移動を伴う述語はゾーン差分に展開する。例: サーチ/指定ドロー =
   `手札+N(該当) ∧ 山札−N(該当)`。破壊 = `場−1 ∧ 墓場+1`。プレイしたスペル自身も墓場+1。
   副作用（山札の特定カード密度が下がる等）はここから機械導出するので、デルタを漏らさないことが最重要。
4. **supply_tags**: そのカードが起こせる効果・イベント・カウンタ操作を `述語(修飾)` 形式のタグにする。
   下のスターター語彙を優先して使い、無い場合のみ同形式で新設する。
5. **require_tags**: 発動要件のうち「デッキ構築の協力が要る（勝手には満たされない）」ものだけタグ化する。
   ファンファーレ単独は含めない。
6. **ヘッドルーム** = 理論最大出力 − 素の出力。`量`が変数X（〜の枚数・〜につき）のカード、
   条件で大きく開くカードは rank を上げる。`rank`: `高`(アンカー候補) / `中` / `低` / `ゼロ`。
7. **不確かな解釈は notes に書く**。勝手に断定して落とすより、候補として残して人のレビューに回す。
8. **存在供給**: 名前指定の存在要求（「自分の場の『◯◯』…」）に対応して、その名前のカード自身と
   それを生成・召喚するカードは `存在(◯◯)` を supply_tags に持つ（これが無いと要求の充足者が索引に居なくなる）。
9. **進化タグの使い分け**: 【進化時】の要求タグは `進化権`。「〜が進化したとき」の要求タグは
   `進化イベント`。効果で味方を進化させるカードの供給タグは `自動進化付与`
   （`進化イベント`要求は満たすが、`進化権`要求＝【進化時】は満たさない）。
10. **構築制約**: デッキ全体の分布で満たす要求（同コストを◯枚、特定カードだけにする等）は
    `構築制約(◯◯)` を使う。例: シャクドウ「引き直し後の手札に同コスト4枚以上」→ `構築制約(コスト分布集中)`。

## タグのスターター語彙

- 供給: `破壊(味方フォロワー)` `破壊(相手フォロワー)` `消滅(相手フォロワー)` `バウンス(味方)` `ダメージ(相手フォロワー)` `ダメージ(相手リーダー)` `ダメージ(自リーダー)` `回復(自リーダー)` `ドロー` `ドロー(指定:◯◯)` `サーチ(◯◯)` `手札生成(◯◯)` `トークン召喚(◯◯)` `リアニメイト(N)` `バフ(攻撃)` `バフ(体力)` `コスト減(手札)` `PP最大+` `墓場+(N)` `スペルブースト+` `進化権+` `進化付与` `守護付与` `疾走付与` `突進付与` `潜伏付与` `必殺付与` `山札密度操作(◯◯)` `味方破壊イベント` `存在(◯◯)`
- 供給（追加）: `自動進化付与` `存在(◯◯)`
- 要求: `覚醒` `ネクロマンス(N)` `スペルブースト(N)` `エンハンス(N)` `コンボ(N)` `連携(N)` `進化権` `超進化権` `進化イベント` `墓場≥N` `存在(自場:◯◯)` `盤面幅(自場フォロワー≥N)` `盤面幅(自場カード≥N)` `手札蓄積(◯◯)` `破壊履歴(味方フォロワー≥N)` `構築制約(◯◯)`

## 出力スキーマ（JSON配列・1要素=1カード）

```json
{
  "card_id": 10632310,
  "atoms": [
    {"requires": ["存在(自場:天晶の魔手)"], "effect": "破壊(自場の『天晶の魔手』, 1)"},
    {"requires": ["存在(自場:天晶の魔手)"], "effect": "ドロー(指定:ウィッチ・フォロワー, 2)"}
  ],
  "deltas": [
    {"zone": "場", "owner": "自分", "filter": "天晶の魔手", "delta": -1},
    {"zone": "墓場", "owner": "自分", "filter": null, "delta": 2},
    {"zone": "手札", "owner": "自分", "filter": null, "delta": 1},
    {"zone": "山札", "owner": "自分", "filter": "ウィッチ・フォロワー", "delta": -2}
  ],
  "supply_tags": ["破壊(味方フォロワー)", "味方破壊イベント", "ドロー(指定:ウィッチ・フォロワー)", "墓場+(2)", "山札密度操作(ウィッチ・フォロワー)"],
  "require_tags": ["存在(自場:天晶の魔手)"],
  "headroom": {"rank": "低", "base": "1コス2ドロー+破壊1", "max": "同左（固定効果）"},
  "notes": "手札デルタは ドロー+2 と スペル自身のプレイ-1 の合算。"
}
```

## few-shot例

### 例1: 燃え盛る魔剣・オルトロス（ナイトメア/F/cost2/2/2）
> 【ファンファーレ】自分の墓場を+2する。 / 【守護】 / 【進化時】【ネクロマンス_4】「相手の場のフォロワーからランダム1枚に2ダメージ。」を2回行う。

```json
{
  "card_id": 10153120,
  "atoms": [
    {"requires": ["ファンファーレ"], "effect": "墓場+(2)"},
    {"requires": [], "effect": "守護(自身)"},
    {"requires": ["進化時", "ネクロマンス(4)"], "effect": "ダメージ(相手フォロワーランダム, 2)×2回"}
  ],
  "deltas": [
    {"zone": "墓場", "owner": "自分", "filter": null, "delta": 2}
  ],
  "supply_tags": ["墓場+(2)", "守護付与", "ダメージ(相手フォロワー)"],
  "require_tags": ["進化権", "ネクロマンス(4)"],
  "headroom": {"rank": "低", "base": "2コス2/2守護+墓場2", "max": "進化+墓場4で除去4点追加"},
  "notes": "墓場+2は純カウンタ増(カード移動なし)。ネクロマンスは消費なので進化時効果は墓場-4。"
}
```

### 例3: ビギンズブレイダー・アマツ（エルフ/F/cost3/2/2）
> 【ファンファーレ】これは+X/+Xする。Xは自分の手札の妖精・フォロワーの枚数である。 / 【守護】 / 【進化時】「相手の場のフォロワーからランダム1枚に1ダメージ。」をX回行う。Xは自分の手札の妖精・フォロワーの枚数である。

```json
{
  "card_id": 10114130,
  "atoms": [
    {"requires": ["ファンファーレ"], "effect": "バフ(自身, +X/+X, X=自手札の妖精フォロワー枚数)"},
    {"requires": [], "effect": "守護(自身)"},
    {"requires": ["進化時"], "effect": "ダメージ(相手フォロワーランダム, 1)×X回, X=自手札の妖精フォロワー枚数"}
  ],
  "deltas": [],
  "supply_tags": ["バフ(攻撃)", "バフ(体力)", "守護付与", "ダメージ(相手フォロワー)"],
  "require_tags": ["手札蓄積(妖精フォロワー)", "進化権"],
  "headroom": {"rank": "高", "base": "3コス2/2守護", "max": "手札上限まで妖精を溜めて3コス10/10級+多点除去"},
  "notes": "量が変数X(手札の妖精数)＝ヘッドルーム大シグナル。妖精を手札に生成する供給と噛む。"
}
```
