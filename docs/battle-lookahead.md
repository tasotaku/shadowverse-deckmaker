# 手札候補から複数ターンを読むAI

[正解照合・時間・メモリ・実対戦の検証記録](evidence/battle-lookahead/validation.md)

対戦ラボ `http://localhost:8767/` のAI欄で **「手札候補から3ターン先読み（試作）」** を選び「AIが一手実行」を押すと使えます。自動対戦にも同じ方式を使えます。右側の「この手のAI判断」に、要求した深さ・完了した深さ・上限・調べた手札の使い方を表示します。以前のAI方式も残しています。

## 候補とターンの数え方

手札を使わない、Aを使う、Bを使う、AとBを使う、といった候補を攻撃・進化・使用順と一緒に探索します。即時点で候補を落とさず、盤面・残り手札・資源・履歴・残り深さが完全一致するときだけ計算を共有します。数値だけの優越判定はしません。

既存の盤面探索から抽選分岐の処理を共用しています。現在ターンの最適方策一つを次ターンへ渡すのではなく、全合法な終了候補を相手の応答まで比較します。現在ターン専用の大盤面向け整数kernelは、この複数ターン探索にはまだ組み込んでいません。

`turns=1` は自分の残りターン、`2` はさらに相手の返し、`3` はさらに次の自分のターンです。境界では通常の `end_turn` 全体を処理します。終了時効果に加えて次手番の開始時効果・PP回復・ドロー・山札切れも含み、次手番の意思決定を増やすかを `turns` で区切ります。

比較は **勝利確率最大 → 同点なら敗北確率最小 → 同点なら盤面・資源点最大**。相手はこの評価を最小にする応答を選ぶ想定です。点数は既存AIの `BASE_WEIGHTS` と特徴量で計算する仮の評価です。ランダム効果は全出目を厳密な有理数で平均し、出目が見えた後に次手を選び直します。

## 実対戦と固定シナリオの違い

通常の `Player` と `/api/ai-step` は公開観測だけを受け取ります。本当の相手手札・山札順・内部乱数は渡しません。公開デッキがあれば残り枚数から、なければ公開カードを参考に、手札・山札の仮定を2通り作り、同じ仮定群で全初手を比較します。

仮定ごとの将来の応答を読む近似で、非公開情報ゲームの厳密解ではありません。仮定間で将来の最善手が異なることもあり、真の情報集合を共有した完全な戦略ではありません。通常AIは要求深さを完了しても **optimal=false、proven_win=false**。相手手札・将来ドローの分布を精密に推定する学習モデルはありません。

診断CLIは明示的に渡した両者の手札と山札順を既知とする固定シナリオを解きます。この条件で全探索が完了した場合だけ `optimal=true` と表示します。実対戦の勝率保証とは区別します。

## 診断CLI

リポジトリルートで実行し、保存先は未使用の場所を指定します。

```powershell
.venv/Scripts/python.exe -X utf8 -m svdeck.battle_lookahead --cases tests/fixtures/battle_lookahead_cases.json --case save_removal_for_next_turn --turns 3 --output output/lookahead-save-three
```

同じケースを `--turns 1` と別の保存先で調べると、今は除去を使う判断から、3ターンでは温存して勝つ判断へ変わります。`case.json`・`report.json`・`report.md` に入力、全初手の勝敗確率、手札使用パターン、最適方策、時間・メモリを保存し、全出力辺を通常Battleで再生します。`hand_patterns` は抽選後の条件付き到達点も含む使用パターン一覧で、出目を自由に選べる意味ではありません。

独立ケースの `n_turns` に合わせて実行してください。

| ケース | turns | 確認する判断 |
|---|---:|---|
| greed_loses_to_return | 2 | 相手リーダーを殴ると返しで敗北、フォロワーを処理して生存 |
| save_removal_for_next_turn | 3 | 今の囮へ除去を使わず、次の守護用に残して勝つ |
| no_play_preserves_end_turn_lethal | 1 | 手札を使わず終了時効果で勝つ |
| incomparable_hand_burn / incomparable_hand_storm | 2 | 同じ手札でも既知の返しにより回復と守護の選択が変わる |
| random_then_observe_and_adapt | 1 | 各1/2の結果を見て生き残りへ確定除去を変え、両方で勝つ |
| end_lethal_precedes_start_and_draw | 1 | 終了時の勝利は開始・ドローより先 |
| start_lethal_precedes_empty_draw | 1 | 開始時の勝利は空山札ドローより先 |
| horizon_boundary_includes_draw_exhaustion | 1 | 境界で山札切れも反映 |
| normal_end_start_refill_draw | 1 | 通常の開始・PP回復・ドロー |

独立参照は `.venv/Scripts/python.exe -X utf8 scripts/lookahead_reference.py` で実行します。新探索を読み込まず、公開Battleの全合法手・全出目から勝敗確率を求めます。共用Battle自体の全ルールの独立証明ではありません。

## 上限と打切り

CLI既定は10,000状態・10秒・1ターン20操作・1操作128出目。`--max-states`（1〜100000）、`--seconds`（0より大〜60）、`--max-actions`（1〜64）、`--max-outcomes`（1〜4096）、`--turns`（1〜5）を指定できます。打切りなら `complete=false, optimal=false, cutoffs=[理由]`。空の方策や停止時点の点数を最適解と扱わないでください。

通常AIは1→2→3ターンの順に深くし、仮定2通りと全深さを合わせて4,000状態・2秒を使います。上限時は完了済みの最深段階へ戻ります。一つも完了していなければ同じ予算で完了した一手評価を使い、それもなければ **未評価の合法手** と明記します。状態上限1などの設定で強い判断は保証しません。方策構築にも時間制限と10,000出力状態上限があります。時間は探索処理で、ファイル保存・CLI再生は計測外。メモリはPythonを含むプロセス生涯ピークです。

巨大な直積を作る前に、カード当たり対象選択欄2種・選択組合せ4096・効果展開10万を超える定義を明示的に拒否します。未対応の効果は通常Battleの定義検証でエラーになります。効果を取り除いて探索しません。

## 既存API・画面から使う

```python
payload = {
    "record": battle.export(),
    "policy": "lookahead",
    "options": {"turns": 3, "max_nodes": 4000, "seconds": 2, "seed": 0}
}
# POST http://localhost:8767/api/ai-step
```

APIが公開観測へ変換してAIへ渡し、選んだ合法手を一つ実行します。返された `decision` とリプレイのフレームに判断が保存されます。

固定ケースを画面で開くには `Battle(case['state'], case['cards']).export()` をJSON保存して **記録を開く** で読み込みます。[温存ケースの保存記録](evidence/battle-lookahead/ui-record.json)も用意しています。演出をOFFにすると操作後の状態をすぐ確認できます。
