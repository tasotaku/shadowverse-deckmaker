# デッキ探索システムの開発経過

更新：2026年9月8日 19:22（日本時間）

**まだ完成していません。独自で、そこそこ戦えるデッキにつながる案を生み出せるかを、実際の探索で検証しています。**

今回は、元の構築の6枚を入れ替え、山札で強化したカードをまとめて引く案を材料に、探索手順を試しています。

今回できたことは、次の3点です。

- 主役カードを指定せずに案を考え、別担当の指摘を受けて比較を追加し、修正案を出すところまで、実際にシステムを使って進めました。
- 追加比較で「入れ替える利点がない」という早い停止判断を見直せました。特定の局面と引き順ではまとめて引く案が勝ち切り、別の引き順では元の構築が先に勝ち切ることが分かりました。
- 参考デッキの取得漏れ、回答形式の説明不足、各評価が参照した資料の分かりにくさを修正しました。最新のコード検査は178件合格です。

**まだ足りないのは、ユーザーが試す理由のある案を残すことです。** 今の案では、必要な局面にどれだけ到達できるか、6枚を入れ替える負担に見合うかが未確認です。指定条件で成立しただけで、強い案として採用してはいません。

直近の追加確認では、相手が除去する順番を変えると、元の18点の手順は場の上限を超えて使えないと分かりました。同じ手札から14点を与えて相手の盤面を全て処理する手順はありますが、入れ替え枚数を減らした案でも再現できます。提案担当は、6枚を入れ替える理由を十分に示せないとして、この配分の検討を止めました。別担当も6枚の変更を試す理由は不足と評価しましたが、補充役を確実に探せる違いは残るため、着想自体は続けて調べる対象にしました。今はこの経過を含め、試行全体で何ができ、何が足りなかったかを採点しています。手法全体の採否はまだ決めていません。

並行して、同じカード資料を使い、「一案を選んで掘る方法」と「複数の着想を短く比較してから選ぶ方法」を比べています。両方が初回の案を1件ずつ提出し、別担当の評価に進みました。後者では、最初に選んだ案が既出と判明して別の着想へ切り替わりました。選び直す工程は動きましたが、残った案も基本の組み合わせは既出で、独自の改善として試す価値があるかは未確認です。

検証を知識として蓄積する一覧・詳細画面の開発は、ユーザーの指示により新しいタスクへ引き継ぎました。手法、検証手順、結果、採否と理由、各工程の開始・終了日時を実際の記録から表示し、今後の作業も継続して記録できる仕組みを作る依頼です。記録していなかった過去の工程時刻は「未記録」として扱います。
