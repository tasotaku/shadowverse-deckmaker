# 探索の記録を使う

探索手法を試す担当が、開始・進捗・結果・採否を記録するための手順です。
一覧で試行を選ぶと、その手法、固定した入力と判断基準、工程時刻、結果、採否理由、保存当時の根拠資料を読めます。

## 画面を開く

Python 3.10以上で、インストール済みのリポジトリのルートから実行します。

```bash
python -m svdeck.experiments init
python -m svdeck.experiments serve
```

[探索の記録を開く](http://127.0.0.1:8765/)。サーバーを起動している間、このPCから使えます。
初期登録は既存の実際の記録だけを取り込みます。2回目以降の `init` は登録済みのIDを上書きしません。

「進行中」から現在の工程と時刻へ、「過去の試行」から結果と採否理由へ進めます。
一覧の本文や「全文」にマウスを重ねると、その場で全文を読めます。小窓の中はスクロールでき、クリック・タップすると開いたままにできます。
「閉じる」、Escキー、または小窓の外のクリックで閉じます。キーボードではTabで本文を選び、Enterで小窓に入れます。
詳細の「根拠資料」には、その報告版を保存した時点の全文が残っています。
「保存・訂正の履歴」で以前の報告へ戻れます。過去版で進行中だった工程の経過時間は、その版の保存時点までを表示します。

## 作業コピーと本体で同じ記録を使う

台帳は `data/experiments.sqlite3` です。ゲーム本体の `data/cards.db` とは別です。
複数の作業コピーから使う場合は、全担当と画面で**同じ `--root`** を指定します。
`--root` は台帳の置き場所と、根拠資料を読み込む本体リポジトリを決めます。
別の場所に台帳を置く場合だけ `--store /絶対パス/experiments.sqlite3` も指定してください。

現在の本体を使う例:

```bash
python -m svdeck.experiments \
  --root /Users/miyauchitsubasa/Desktop/github/shadowverse-deckmaker serve
```

一覧の「記録の保存先」で、画面が読んでいる台帳と原本の場所を確認できます。
元タスクが `evals/` や `docs/` の資料を更新すると、次の読込みで「原本に未取込の変更」が表示されます。
資料の変更だけで試行結果や採否を自動変更しません。報告を確認して保存すると、新しい資料も別版として残ります。

## 新しい試行を記録する

画面の「試行を記録」から、ねらい・入力・判断基準を記入し、まず「未着手」で保存できます。
不明な本文項目には「未記録」、不明な実施日時には空欄を使います。
記録者と更新理由は保存ごとに必要です。

CLIを使う担当は、ひな形を書き出して編集します。

```bash
python -m svdeck.experiments template > /tmp/experiment.json
# /tmp/experiment.json に実際の内容を記入した後:
python -m svdeck.experiments create /tmp/experiment.json \
  --actor '担当名' --reason '入力と判断基準を固定して開始前に登録'
```

`id` は試行を通して同じ値を使います。英小文字・数字・ハイフン、80文字以内です。
`evidence_paths` は本体の `evals/`・`docs/` 配下の相対パス、または `README.md` の配列です。
ディレクトリを指定すると、後から増えた資料も変更検出・保存の対象になります。
資料は各10MB、1試行の合計50MB以内。カードDBは資料として取り込みません。

## 工程を開始・更新・終了する

画面では「進捗・報告を更新」から工程を追加し、開始日時と状態を記録します。
終了したら終了日時と結果を追記します。「今の日時」は**その場で実施したとき**に使います。
過去の作業の日時に現在時刻を入れないでください。

CLIでは最初に現在の版番号を確認します。

```bash
python -m svdeck.experiments show trial-02

python -m svdeck.experiments stage trial-02 proposal-1 \
  --title '初回の考案' --status running --at now \
  --experiment-status running --budget-minutes 25 \
  --note '固定した資料で考案を開始' \
  --expect 1 --actor '担当名' --reason '初回工程の開始を記録'

python -m svdeck.experiments stage trial-02 proposal-1 \
  --status completed --at now --note '回答と操作記録を保存' \
  --expect 2 --actor '担当名' --reason '初回工程の終了を記録'
```

`--expect` は編集元の版番号です。他担当が先に保存すると更新は拒否されるので、最新版へ自分の変更を合わせます。
CLIの `--at` はタイムゾーン付きの日時（例 `2026-09-08T19:20:00+09:00`）も受け付けます。
省略すると日時を補いません。記録済み時刻の訂正は次節の `update` を使います。

待機へ移るときは作業工程を完了または中断として閉じ、待機の工程を新しいIDで記録します。
再開も新しいIDにします。これで作業と待機の期間が混ざりません。
並行する担当には別々の工程IDを使います。画面は各工程の時間を表示し、合算を総経過時間として表示しません。
試行全体の開始・終了が不明なら、全体の経過は「未記録」です。
記録上の「作業中」は、実行プロセスが今も動いている証明ではありません。

## 結果と採否を記録し、試行を閉じる

試行結果は `result`、手法を使う判断は `decision` に分けます。
たとえば「手順は成立した」ことと「この方法を採用する」ことは別の判断です。
採用・却下・保留には理由を残し、判定していないものは未判定のままにします。
試行を完了・中断にする前に、作業中・待機中の工程を閉じてください。

CLIで報告全体を更新する場合:

```bash
python -m svdeck.experiments show trial-02 --record-only > /tmp/experiment.json
# 実施内容、結果、残る問題、採否と理由、実施時刻を編集した後:
python -m svdeck.experiments update /tmp/experiment.json \
  --expect 3 --actor '担当名' --reason '独立評価を受けて結果と採否を記録'
```

保存するたびに全報告の新しい版を追加します。以前の本文・日時・根拠は消しません。
訂正する場合は「どの値を、何を根拠に訂正したか」を理由に書いてください。
入力と判断基準を途中で変える場合も理由を残します。同じ条件で比較した試行とは扱わず、条件を変えた再試行は新しいIDにします。

## バックアップと別PCへの復元

台帳には全報告版と根拠資料の実データが入っています。ブラウザの一時保存ではありません。
台帳は `data/` 配下のため、通常のGit操作だけではバックアップされません。
区切りや移行前に次を実行し、生成したファイルを別の保存場所へ保管してください。

```bash
python -m svdeck.experiments backup /保存先/experiments-20260908.sqlite3
```

この操作は更新中でも整合したコピーを作ります。同名の既存ファイルは上書きしません。
別PCへはリポジトリのコードと、このバックアップファイルを移します。
[READMEの準備](../README.md#準備)に従い、新しいリポジトリで仮想環境を作って `python -m pip install -e .` を実行してから復元します。

```bash
python -m svdeck.experiments restore /移した場所/experiments-20260908.sqlite3
python -m svdeck.experiments serve
```

`restore` は既存の台帳を上書きしません。既存の記録がある場所では、まず別の `--store` へ復元して内容を確認します。
元の `evals/` や `docs/` がまだなくても、復元した台帳から保存済みの根拠を読めます。
新しい資料を取り込み続けるには、同じ相対配置の `evals/` と `docs/` を戻し、正しい `--root` を指定してください。

## 保存形式と初期登録の根拠

SQLite（1ファイルに記録を永続保存するデータベース）に、追記専用の2種類を保存します。

| 保存対象 | 内容 |
|---|---|
| `revisions` | 試行ID・版番号・サーバー保存時刻・記録者・更新理由・報告全文・根拠の一覧 |
| `blobs` | SHA-256（内容が同じかを照合する識別値）と、根拠資料の元のバイト列 |

報告の `started_at` / `ended_at` と工程内の同名項目は実施日時、`saved_at` は台帳への保存日時です。
日時はタイムゾーン付きの値を保存し、画面では日本時間を表示します。元の精度は変更しない限り保持します。
新しい記録は `create`、全体更新は `update`、工程更新は `stage`、読出しは `list` / `show`、退避と復元は `backup` / `restore` を使います。
画面も同じ保存処理を使い、HTTP入口は `GET /api/experiments` と `POST /api/experiments` です。HTTPの更新には画面が取得するトークンが必要です。

初期登録内容は `src/svdeck/data/experiment_catalog.json`、出典の照合記録は `evals/journal/catalog-provenance.json` に残します。
過去の試行結果は当時の検査範囲の結果で、探索方式全体の性能や実戦勝率を示しません。
この画面の開発だけを理由に、探索方式を採用へ変更していません。
