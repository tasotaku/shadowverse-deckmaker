# 現在ターンの全候補列挙の検証

対象は `svdeck.battle_frontier` のPython・CLI・HTTP入口です。相手の返しは含めず、自分の現在ターンで止められる全状態と、合法な操作・確率枝を保持します。

## 正確性

- 独立担当が作成した8ケース・41状態・37辺・27手計算手順。
- 固定seedによる24ケースと、既存の複合能力6ケース。
- 新規174テストで全到達状態・全操作・確率・条件付き再生を独立全列挙と比較。候補の成分比較、低スタッツでの相打ち、大小比較不能、無駄なpingの除外、境界上限、入力の保持、HTTP入出力も検査。整数kernelには96seedの遷移照合を追加し、圧縮形式の境界・大整数への退避も確認。
- 圧縮版の対戦関連回帰テストは704件PASS、54.44秒。新規174件だけの実行もPASS（7.35秒）。型検査は変更9ファイルPASS。検証worktree `8ff3337` と反映先 `253620e` の製品ファイルは同一。
- 起動中の `http://127.0.0.1:8767/api/turn-frontier` から高速経路の4状態・4候補、汎用経路の9状態・6候補を取得し、全件完了と自分の手番の維持を確認。

圧縮前 `99b8ccc` の独立受入T1はPASS。専用CLIを8回、HTTPを1回、それぞれ再試行なしで操作し、全状態・行動枝・有理数確率・27手順が独立オラクルに一致しました。候補集合から除外した6状態は、独立consumerが残り手札と資源を含む優越理由を確認しています。[T1報告](acceptance-small-packed/report.json) / [実測値](acceptance-small-packed/measurements.json)。

圧縮版にも別のfresh担当が同じT1を1回実行してPASS。全41状態・37分岐・27例・35候補に加え、全41状態への公開手順の再生が一致しました。fixture内のping消費例は、固定仕様F4で明示された「同じ盤面で手札とPPを余計に消費する」除外として、根拠と元の経路を残しています。[圧縮版T1報告](acceptance-compact/report.json) / [計測値](acceptance-compact/measurements.json)。

独立参照も戦闘ルールには公開Battleを使います。探索の候補欠落・確率処理の独立検査であり、Battleの全ルールそのものの独立証明ではありません。大盤面の全数性は、独立全状態オラクルより弱い「探索済み状態数・全操作展開の整合性とサンプル再生」の確認です。

## 計測の読み方

大盤面は `tests/fixtures/battle_lookahead_hard.json` の `hard_full_board_branching_1` と `hard_full_board_branching_2` を使用します。両者5体、自分の手札6枚、5種の能力と指定・ランダム・割り振り・除去・召喚・付与を組み合わせた局面です。

各ケースを新しいCLIプロセスで実行し、解析内の時間・メモリに加え、独立担当がOSから実Pythonプロセスの最大常駐メモリと起動から終了までの時間を計測します。完全列挙と上限打切りは別に記録します。大きい `graph.json` は `output/` に保存し、検証報告にファイル位置・サイズ・hashを残します。

初期の汎用実装はhard1で600秒・2,429,145状態まで到達しても未完了でした（OS peak 4,170,850,304 bytes）。この結果を成功扱いせず、単独効果の閉じた条件を整数で処理する経路と、辺の圧縮保存を追加しました。整数経路に対応しない複合効果は汎用処理へ戻します。

整数経路 `99b8ccc` でも、hard1は1,000万状態・71,506,729出目で状態上限に到達しました。解析578.49秒（うち列挙387.63秒）、最大常駐9,295,020,032 bytes、候補2,124,230件ですが、**列挙は未完了**です。`frontier_complete=true` は「到達済みの状態の候補整理が終わった」という意味で、全件列挙の保証には `complete=true` が必要です。固定仕様の600秒・1,000万状態での完了要件を満たした扱いにはしません。

この時点の工程確認では、遅さの原因を同一検証の繰返しではなく「必要な状態数と保存量」と分離しました。固定受入の期待・入力・予算は変えず、失敗記録を維持します。次の製品変更では比較ベクトルの表現だけを圧縮し、別途大きい予算を指定する計測を可能にします。上限拡大の計測は固定受入の合格への置換ではありません。

同じ固定予算でhard2は8,661,088状態・62,109,857出目・1,643,067候補を全件完了しました。CLI全体614.26秒、OS peak8,025,923,584 bytesです。固定受入の総合結果はhard1の未完了による **FINDINGS 1件**。状態上限・時間上限の明示、標準JSONの全体検査、公開APIによるサンプル再生は合格しました。[固定予算の統合報告](acceptance-fixed-99b8ccc.json)。

独立受入では「未攻撃」と「顔を殴って攻撃権を消費した結果」を同一比較群に置く問題も検出しました。攻撃権・登場ターンを比較条件へ追加し、両候補を保持する回帰テストを入れています。
