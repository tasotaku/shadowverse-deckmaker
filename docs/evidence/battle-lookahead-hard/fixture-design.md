# 複数ターン先読み・難問ケースの設計

作成日: 2026-09-24。対象: `tests/fixtures/battle_lookahead_hard.json`。

新探索 `src/svdeck/battle_lookahead.py` を読まず、公開 Battle と既存の独立参照 `scripts/lookahead_reference.py` から手作りした。製品コードは変更していない。全8件とも `n_turns=3`。自分の残りターン、相手の返し、次の自分まで読み、最終 `end_turn` の開始時効果・ドローまで含む。

## 正解と計算量の検査を分ける

6件は `classification="exact"`。独立参照の全合法初手の厳密な有理数 `(勝率, -敗率)`、最適初手の集合、探索状態数を保存した。未決着は `(0, 0)`。`expectations.action_values` は抜粋ではなく全初手である。手札の同時使用・温存・使用順は各初手以降の全合法行動から探索する。

2件は `classification="stress"`。双方5体、全員攻撃力1以上、各側手札6枚、PP5。各側を手番にした時に攻撃できる異なる個体が5体あることを実測した。初期の守護を破壊すると攻撃対象が増え、空いた盤面に疾走トークンを召喚できる。攻撃済み・召喚酔い・攻撃力0の置物で5体を水増ししていない。

stress は独立参照を各30秒で打ち切った。`reference` に上限、実時間、プロセスID、停止後終了コード、`process_terminated` を保存した。`Popen.communicate(timeout=30)` の期限後に `kill()` と `communicate()` で終了まで回収し、`poll()` で終了を確認した。期待値は保存していない。探索が合法手を返す、時間内に止まる、出力辺を再生できることと、正解を証明できることを混同しない。

## ケースの狙いと観測

| ID末尾 | 組合せと手順 | 将来ターンでの差 |
|---|---|---|
| barrier_bane_return | 必殺・守護・バリア、指定ダメージ、味方へのバリア付与。pingは敵のバリアを消費、protectは反撃被害を変える。攻撃初手も現Battleでは勝てる。 | 終了初手は相手の返しで負け。攻撃を含む有効手順なら次の自分で勝つ。 |
| oldest_barrier_split | 古いバリア守護にping→4点割り振りで両守護が消える。逆順だと古い守護が体力1で残る。新しい守護へのpingも最適ではない。 | 今のターンでは勝てず、正しい初手だけ3ターンで勝率1。パスは返しで負ける。 |
| summon_then_grant_storm | 召喚→全味方に疾走→即攻撃。付与→召喚だと新トークンは疾走を受けない。相手手札にも守護と突進がある。 | 正順は今すぐ勝利。逆順・パスは相手の返しがあり、3ターン以内の勝利を強制できない。 |
| random_barrier_remove | 指定破壊でバリア守護を今除去する。ランダム1点は温存可能。2枚あるがPP1なので今両方は使えない。 | 守護破壊だけが3ターン勝率1。脅威破壊は未決着、ランダムダメージ・パスは返しで敗北。 |
| rush_grant_bane | 突進を出す→その個体へ必殺付与→大型守護と相打ち。先に既存の味方へ付与するとPPと手札が尽きる。 | 正順だけ次の自分に既存の味方がリーダーへ到達。付与先を誤る初手・パスは返しで敗北。 |
| random_destroy_preserve_targeted | 指定2点で必殺の脅威を先に倒し、ランダム破壊を次ターンへ残す。 | 正しい指定先なら3ターン勝率1。ランダム破壊初手は敗北確率1/2。バリアへの指定ダメージは確定敗北。 |
| full_board_branching_1 | 5対5、各6手札。指定/ランダム/古い順/確定除去/召喚/付与と全5キーワードを同時に有効化。 | 返しの全攻撃・全手札、次ターンの残存個体・手札へ分岐。正解未確定。 |
| full_board_branching_2 | 同じ能力群で盤面の古さと手札順を変更。古い順の割り振り先が変わる。 | 同じく返し・次ターンまで計測する高分岐ケース。正解未確定。 |

最初のexact検査では全6件が完了した。合計856状態。5件は深さ1・2の最適値が `(0,0)`、深さ3で `(1,0)` に変わる。召喚→疾走ケースだけは深さ1でも勝てる対照ケース。各 `metadata.horizon_values` に実計算値を保存した。

## 独立した手順の期待状態

8本の `replays` に手計算の `expected_paths` を保存し、既存参照の `verify()` で通常Battleへ再生して全件一致を確認した。

- バリアへの1点で体力が減らずバリアだけ消える。
- 現Battleでは必殺攻撃のダメージをバリアで防いでも対象は破壊される。
- 古いバリアに配分した2点は遮断されても消費され、新しい守護には残り2点が入る。
- ping→割り振りと割り振り→pingの順序差。
- 召喚→全体疾走と全体疾走→召喚の差、前者の即時勝利。
- 突進→必殺付与→攻撃で大型守護と相打ちし、元の味方が残る。

Battleは参照と新探索が共有する遷移エンジンである。これは探索の独立照合であって、実ゲームの全ルールの独立証明ではない。特にバリアと必殺の実ゲーム裁定はこの検査では判断・変更していない。
