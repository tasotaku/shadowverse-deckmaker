# 過去の探索経験をカードと使い方から再利用する

探索システムに追加した検索補助の採否を判断する報告です。**過去の正式案・評価・残った条件を検索し、原資料へ戻れる補助を採用しました。新規担当による実記録3課題はすべて合格です。** 新しい種の発見力を認定した結果ではありません。本体CLIでの一致確認まで完了し、最終の記録・配信を進めています。

## 何を変えたか

以前は別探索の記録を取り込むには、元ファイルの場所を知る必要がありました。新しい `discovery recall` は、カードIDと使い方の検索語から、案全文・評価全文・元の条件・出典対応を読み取り専用で返します。カードIDはその案の役割にあるものへ照合し、資料に含まれるだけのカードを混ぜません。

同じ案の複製はまとめ、別の改訂や異なる評価は両方残します。壊れた記録は探索名と理由を返し、一致なしと取り違えさせません。カード注記や新しい入力版へ自動追加せず、旧判定を新しい採否へ適用しません。

## 検証した手順と結果

不足と最小設計を固定 → 隔離した場所で実装 → 正常・境界・失敗の検査 → 新規担当の実利用 → 元記録と固定条件へ照合 → 本体へ反映、の順で進めました。

初期の別点検で、固定資料だけが欠けた探索、元案だけが欠けた評価が検索から消える問題を見つけました。2件ともテストで再現して修正しています。新規20件と既存66件、型検査に合格しました。初回の別の1失敗は、テストが元案の最初の20行だけで末尾を期待していたためで、正しく末尾まで読む検査へ直しました。

新規担当には事前の採点条件や他担当の回答を渡さず、公開の検索・読出し・レポート入口だけを使わせました。全体は5分16秒（315.924秒）で終了しました。

| 課題 | 実際に確認できたこと | 判定 |
|---|---|---|
| 2つのリッター案を復元 | ラスティ型は追加検討、旗型2版は比較試用という過去判断と、利益・負担・未確認を区別 | 合格 |
| 2カードが関わる案を絞る | 1系列・2改訂・2保存先・4保存物・正式評価1件を区別。未評価の初版へ評価を流用しない | 合格 |

総数3課題＝合格3件・不合格0件。別担当が全回答と元評価・公開操作を照合しました。ラスティ案の全222行と関連カード本文を実際に再読し、保存元316ファイルと入力3ファイルも不変でした。

記録された公開操作は21回（検索9・元資料読出し8・レポート4）で終了コードはすべて0です。一方、正式な保存先を使う前に短縮パスを入口で3回拒まれたと本人が申告しています。この3回には時刻付き記録がないため、全操作を無失敗とは扱いません。

## 採用理由と残る問題

元の案・評価・残った条件を取り出せることと、本体でも全返却内容が一致することを確認できたため、**検索補助として採用**しました。保存時点の判断を保持し、次の独立評価へ旧判定を自動で混ぜないことも確認しています。

ただし、新しい種の発見力・勝率・独自性は評価していません。文字列による検索なので、別の表記や未登録の経験は見逃します。正式記録がすべて失われた探索は復元できません。

返却量も課題です。最初のリッター検索は約146KB、繰り返しを含む全公開出力は1,254,442バイトでした。カードと用途へ絞って使う必要があります。速度比較の対照群はなく、この量だけが所要時間の原因とは判断していません。
