# 記事の採用理由と入れ替え候補を入力に残す

**記事の説明を保存する取得補助として採用します。** 指定した2記事から、40枚の内訳・出典情報・説明の計6資料を保存し、すべて原文どおり読み返せました。別担当も保存資料だけから、候補の使い方と掲載範囲を39秒で復元しました。新しい種の発見力は、この試行では評価していません。

## なぜ試したか

前のナイトメア探索では40枚の内訳だけを初期資料に入れました。その後の調査で、同じ記事の入れ替え候補欄に、案と重なる使い方が書かれていたと分かりました。取得した記事の説明を捨てる現在の入口を直す必要がありました。

## 手法と実際の手順

1. 実装前に[条件](protocol.json)を固定し、GameWithとGame8の実HTMLで本文の境界を確認しました。既存のGame8検査用HTMLは本文を省いた資料なので、本文抽出の成功例には使っていません。
2. `meta --article URL --format rotation --with-article-text` を実装しました。1回の取得から既存の40枚解析と説明の抽出を行い、同じ観察日時で出力します。本文の最初の大見出しから関連記事の前まで、見出し、表の行、画像のカード名を保持します。隠し表示のカード効果、目次、広告、コメントを採用理由に混ぜません。
3. 51件の機械検査と2ファイルの型検査に合格しました。別担当も元HTMLと抽出結果を照合し、候補8行のカードと理由が対応することを確認しました。
4. 公開コマンドで2記事を新たに取得し、全40枚・説明・取得情報を正式6資料として追加しました。保存版の285行を4回に分けて読み、行を連結して元の全項目と一致することを確認しました。カードDBの識別値も変更前後で一致しました。
5. 会話・コード・以前の評価を渡していない別担当が、同じ公開読出しを3回使い、全285行を読みました。カード名を指定しない問いから、候補欄の使い方と、40枚リストへの採用の違いを説明できました。

公開操作は[実行記録](public-events.json)、元の出力は[GameWith](gamewith.json)と[Game8](game8.json)、保存後の一致は[照合結果](roundtrip.json)、別担当の利用結果は[読出し確認](reader-check.json)に残しています。

## 結果と採用理由

GameWithのミッドレンジナイトメアでは、アズヴォルトをイステンデッドで破壊して盤面へつなぐ説明が候補欄に残りました。別担当は、そのカードがメイン40枚に入っていないことも区別しました。この確認では、候補名や答えを資料の外から与えていません。

Game8のフェイスドラゴンでは、早期決着を目指す全体方針を本文から読めました。一方、個別カードの枚数理由は本文になく、表示37枚とコピー対象40枚の差が生じた原因も不明のままです。欠けた説明を推測で補うことはありませんでした。

**採用するのは、記事の説明を初期資料へ残し、同じ保存版から再利用できる取得補助です。** 以前は入力に無かった用途を、今回の公開入口で保持して読み返せたためです。通常の全40枚取得は維持し、説明追加は任意の指定で使えます。本文の取得・再利用を、デッキの強さや独自性の認定へ広げません。

- 初回の台帳登録は結果状態に存在しない値を指定して拒否されました。所定の未判定値へ修正して登録しました。実際の試行開始時刻は変更していません。

- 本文が見つからない・空・閉じない・重複する場合は取得不能を明示し、カード名を読めない画像は部分欠落として識別値を残します。画像内の文字、動画、動的表示は未確認です。
- 「変わりし流れ」の理由が途中で切れるのは、元HTMLも同じ状態です。補完していません。
- 2サイト各1記事の実利用です。両サイト全ページの対応保証、公開用途の普及率、新しい案の考案、勝率や手法全体の優位は未評価です。元のナイトメア案・旧評価は変更していません。
