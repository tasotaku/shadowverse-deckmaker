# 得たPPや手札の別用途を探して、元案と比べる

**比較は完了し、本採用を保留しました。変更版は別用途を1案検討しましたが、追加して試す利点が足りず、その案を見送りました。** 最終の試用推薦は現行0件・変更版1件ですが、変更版の推薦は元案への評価です。追加した探索手順の成果とは数えません。独自で有用な着想の確認は両方0件で、システム全体は未完成です。

## なぜこの方法を試すか

直前の調査では、基本用途の先例は確認できましたが、案全体の独自性や一般的な普及は未確認でした。記事を渡す機能だけでは、そこから別の着想へ発展できたとは言えません。先例で確認できた手順を材料に、得られるものの使い先を一度変えて探す工程を試します。

元案が既出というだけで捨てる指示ではありません。別用途を見つけられなければ、調べた範囲と未達を残して元案を選べます。既存手順の選び直し、順番や枚数だけの変更、同じ仕事の担当交代は、この変更が狙う発展の成果に数えません。

## 実装と検証手順

1. 同じ正式案・評価・固定カードDB・記事・先例調査・別照合を使う条件を開始前に固定しました。保存資料は24件です。過去案を含む開発用比較で、未知の着想を発見した検査とは呼びません。
2. 現行方式は通常の改訂を行います。変更版にだけ、使える時点と残PP・手札・場・進化権を確かめ、別の使い道を一つ置いて既存検索とカード本文へ戻る指示を加えました。追加するカードを外すと何ができなくなるか、追加の準備と失う元の役割も、通常構築と同じ状態から比べます。個別カードや具体的な使い道の答えは開発者が指定していません。
3. 本体とは別の作業場所で、改訂指示だけを変更しました。コード10行と一般的な設計注記6行で、DB・提出形式・採点基準・実行機能は変更していません。初回考案・別評価・保存調査からの提案化の指示は維持しています。
4. 関連131件（既存122件＋新規の境界確認9件）と型検査2ファイルに合格しました。保存済み案の有無、最新案の自動選択、新規の枝、引き継ぎ指定、無効な入力を固定版と照合しています。公開読出しの全文一致も確認しました。
5. 検査の初回に、未存在の改訂が返す例外型、弱い本文一致の検査、型と環境設定を訂正しました。最終結果の前に訂正した内容を[実装報告](implementation.json)へ残しています。これらの機械検査は、実AIの指示遵守や発見力を証明するものではありません。
6. 両方式の実装と入力を固定しました。現行の実入力と変更版で作った入力を全文比較し、差分が改訂指示だけであることを確認しました。変更版の実際の開始後も、同じ入力版であることを確認済みです。後続の別評価工程も開始前に登録・点検しました。

両方式とも改訂15分・別評価10分を上限に各一度実行しました。両方とも正式な改訂と評価を各1件保存し、明示した終了要求で停止しました。回収時に元資料・固定実装・正式提出・終了処理の保持を再照合しました。失敗を含め、追加実行によるやり直しはしていません。

## 結果と採否の理由

| 観察したこと | 現行 | 変更版 |
|---|---|---|
| 新たに保存した改訂・別評価 | 各1件 | 各1件 |
| 最終評価 | 追加検討 | 元案への限定試用推薦 |
| 新しい別用途の案 | 今回の狙いに該当する確認なし | 1案検討、追加採用見送り |
| 新しい別用途への試用推薦 | 0件 | 0件 |
| 有用で独自な着想の確認 | 0件 | 0件 |

変更版は、手順の途中で回復した4PPを、ターン終了時に味方へダメージを与える札へ使う案を検討しました。相手の攻撃力が低くても味方を破壊して手札を補充できます。ただし場を空けるための相打ちは必要で、相手の場が空か攻撃力0だと使えません。追加札を使わない同じ手順との比較では手札が3枚増える一方、場とアーティファクトを用意する役割を失います。通常構築との比較での手札差は1枚です。追加札が以後の自分の場にも損害を与えるため、追加採用を見送り、別評価もその判断を支持しました。

この比較では候補札／比較札をそれぞれ1枚加えた6枚の手札を使い、元の5枚条件からの変更を明示しています。必要札を揃えられる頻度は未確認です。成立範囲を広げたことや検索件数だけを、試す価値の証拠にはしていません。

変更版の最終推薦は、追加札を外して元の配分に戻した案へのものです。さらに評価者が「全処理後に残る4PPで、手札のミューを進化せず置く」という手順を補っていました。現行も元案から進化権を残す手順へ進んでいますが、ミューを手札に残す終点では利益の根拠が不足すると評価されました。評価者の追加手順と判断の差が混じるため、推薦0対1を指示変更の効果とは認定できません。

**開始前に決めた、変更版だけの実質的な発展に試用理由が残る条件は未達です。** 指示は本体へ採用せず、成功を前提にした別の新規入力での検証へも進めません。否定的な結果として、場が埋まる条件・相手への依存・失う通常構築の役割は再利用できる形で残しました。一回の既知入力の比較であり、この方法が常に無効だと確定したわけではありません。

基本用途の先例は既存入力で調査・別照合済みです。今回の最終案について案全体の一致例・一般的普及は未確認のままですが、新たな調査対象が特定されていない同じ残問の再検索は追加しません。新枝は試用推薦がなく、今回は後続の先例調査を実施しないと両方式同じ条件で判断しました。元の評価・採点基準は変えていません。

## 失敗と確認範囲

変更版は改訂提出時にカードの役割の重複・取得区分の検査で1回、別評価提出時にカード本文等の参照検査で1回拒否され、同じ実行内で訂正して正式保存しました。公開操作は現行56回・47回、変更版28回・140回です。操作回数を発見力や速さの成果にはしません。

両方式の実入力は改訂指示だけが相違し、各実装・元入力・旧案・旧評価・本体DBは保持されていました。正式な改訂・評価は総数4件＝確認済み4件です。131件の機能検査・型検査の合格と、今回の有用性評価を分けています。実戦の勝率・必要札の到達頻度・一般的な発見力は未検証です。

## 次の改善へ戻す点検

取得元の参照資料、多段の取得元を保存する形式、生成札の能力を生成元の検索にも使う機能は既にありました。今回除外された効果札3件は資料にありますが、その札への参照元は3件とも0件でした。参照がない理由は未確認で、取得不能とは断定しません。単純な逆引き追加で改善する証拠はなく、その新設案は見送りました。[既存機能との照合](route-audit.json)。

一方、変更版が読んだ検索8問はすべて検索用の条件が未指定で、型検索は実行されていませんでした。手元のカード本文とタグを調べた結果とは区別します。この点検から、考案中に新しく生じた条件を正式案の提出前に既存検索へ渡す入口がないことを確認しました。その後の実装・実利用と検索補助としての採用は、[次の検証記録](../live-query-01/README.md)に分けて保存しています。別用途の指示は採用していません。
