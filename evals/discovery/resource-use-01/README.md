# 得たPPや手札の別用途を探して、元案と比べる

**現行方式は改訂を終えて別評価中、変更版は改訂中です。変更版の機能検査は合格しましたが、方法の有用性と本採用は未判定です。** ここで試すのは、既に確認した手順で得られるもの（使えるPPや手札など）の使い先を変え、これまでの案にはない働きができるカードを探す動作です。新しい案は一つだけ比較し、元案も選べるようにします。

## なぜこの方法を試すか

直前の調査では、基本用途の先例は確認できましたが、案全体の独自性や一般的な普及は未確認でした。記事を渡す機能だけでは、そこから別の着想へ発展できたとは言えません。先例で確認できた手順を材料に、得られるものの使い先を一度変えて探す工程を試します。

元案が既出というだけで捨てる指示ではありません。別用途を見つけられなければ、調べた範囲と未達を残して元案を選べます。既存手順の選び直し、順番や枚数だけの変更、同じ仕事の担当交代は、この変更が狙う発展の成果に数えません。

## 実装と検証手順

1. 同じ正式案・評価・固定カードDB・記事・先例調査・別照合を使う条件を開始前に固定しました。保存資料は24件です。過去案を含む開発用比較で、未知の着想を発見した検査とは呼びません。
2. 現行方式は通常の改訂を行います。変更版にだけ、使える時点と残PP・手札・場・進化権を確かめ、別の使い道を一つ置いて既存検索とカード本文へ戻る指示を加えました。追加するカードを外すと何ができなくなるか、追加の準備と失う元の役割も、通常構築と同じ状態から比べます。個別カードや具体的な使い道の答えは開発者が指定していません。
3. 本体とは別の作業場所で、改訂指示だけを変更しました。コード10行と一般的な設計注記6行で、DB・提出形式・採点基準・実行機能は変更していません。初回考案・別評価・保存調査からの提案化の指示は維持しています。
4. 関連131件（既存122件＋新規の境界確認9件）と型検査2ファイルに合格しました。保存済み案の有無、最新案の自動選択、新規の枝、引き継ぎ指定、無効な入力を固定版と照合しています。公開読出しの全文一致も確認しました。
5. 検査の初回に、未存在の改訂が返す例外型、弱い本文一致の検査、型と環境設定を訂正しました。最終結果の前に訂正した内容を[実装報告](implementation.json)へ残しています。これらの機械検査は、実AIの指示遵守や発見力を証明するものではありません。
6. 両方式の実装と入力を固定しました。現行の実入力と変更版で作った入力を全文比較し、差分が改訂指示だけであることを確認しました。変更版の実際の開始後も、同じ入力版であることを確認済みです。後続の別評価工程も開始前に登録・点検しました。

両方式とも改訂15分・別評価10分を各一度実行します。失敗や時間切れを保存し、追加の改訂で成功回数を増やしません。必要な後続調査は、結果回収後に同じ条件で適用を判断・登録します。

## 成果と採否の基準

通常構築に対して試す理由と、一般に広まった使い方の言い直しではない根拠がある着想を主成果として数えます。検索回数・資料数・新しい組み合わせが増えただけでは成果にしません。試用推薦と独自性未確認は分けて記録します。

変更版だけに実質的な発展と試用理由が残った場合に、別の新規入力でも確認します。現行も同じ発展を見つけた場合は、変更の上乗せ効果を認定しません。今回の結果だけで本体へ採用せず、一回の比較を一般的な優位の証明にしません。実戦の勝率やTierは今回の検査対象ではありません。
