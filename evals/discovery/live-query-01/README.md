## 何を改善したか

既存の検索は、提出済みの案に保存された問いを次の入力へ作る際に使います。考案中に思いついた条件を、その場で固定データの検索へ渡す公開操作がありませんでした。元の入口で操作が拒否されることも確認しました。

今回の入口は、問いと検索用の条件を1件ずつ受け取り、既存の条件検索を実行します。採用可能な候補の番号と、同じ保存資料で本文・進化・参照先・注記を読む位置を返します。検索そのものでは元の案・評価・資料を変えず、必要な結果は既存の添付機能で残します。

## 実利用の結果と採用理由

実担当は、必要なフォロワーを手札に残せる頻度が未確認という課題から、「フォロワーを引く補助手段」を検索する問いへ具体化しました。旧検索の問いと条件をそのまま再実行したものではありません。

検索は候補を1件返し、本文でもフォロワー1枚を引く効果を確認できました。ただし特定の2枚を確実に揃える効果ではなく、必要なPPや場の空き、他のフォロワーを引く可能性が残ります。担当は確定サーチや手順成立へ話を広げず、採用枠と序盤に失う役割、実際の利益は未確認としました。

**提出前の新しい条件を既存検索へ渡し、根拠を確認・保存・再読するという採用条件を満たしました。** その範囲の検索補助として採用します。使える工程は考案に限り、別評価・調査・別照合の操作範囲は広げていません。

候補は検索前にも読まれていたため、候補を知らずに新しいカードを発見した証拠にはできません。0件の場合に実担当がどう続けるかも、今回の実利用では未確認です。型検索の一致、実際の手順成立、試す価値、独自性を分けています。有用で独自な着想の新たな確認は0件、正式案・正式評価の追加も0件です。
