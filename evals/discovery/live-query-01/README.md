# 考案中の新しい条件を、その場で検索する

**公開操作に入口がないことを確認し、実装・検査を始めます。有用性と採否は未判定です。**

既存の検索は、提出済みの案に保存された問いを次の入力へ作る際に使います。考案中に思いついた条件をその場で渡す操作はありません。本文やタグを手元で調べることはできますが、既存の型検索へ渡したことにはなりません。

今回追加するのは、問いと検索用の条件を1件ずつ、同じ固定データの既存検索へ渡す入口です。採用可能な候補を返し、本文と注記を読む手掛かりにします。一致しただけで、手順の成立や強さは認定しません。

## 手順と採否

1. 入力と実装、検査条件を固定し、隔離した作業場所で入口を追加します。既存の探索指示・採点・保存内容は維持します。
2. 未提出の検索、条件が一致しない場合、不正な入力、違う工程・終了後からの操作、固定入力の保持を機械検査します。目安12分です。
3. 保存済みの入力を使い、実担当が新しい問いを一つ選んで検索し、本文・注記との照合を既存の追加資料に保存します。上限6分・一度だけです。
4. 別担当が検索・保存内容と限界を確認します。目安3分です。未提出の新要求を検索でき、その根拠を保存・再読できた場合に検索補助としての採否を判断します。

今回の比較で案が不採用になった理由を、この入口だけで解消できる証拠はありません。検索補助の動作確認と、有用で独自な着想が増えるかの評価を分けます。新しい発見の確認件数は、現時点で0件です。
