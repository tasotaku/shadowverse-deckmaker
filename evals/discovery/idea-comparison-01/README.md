# 着想を短く比較する手順の試行1

同じローテーション・エルフの資料を使い、現行の一案を選ぶ進め方（a）と、最大3件の着想を短く比較して記録してから選ぶ進め方（b）を試す。標準の考案・評価指示は変えず、既存の資料追加と提出の公開入口を使う。**両方式の初回を実行中。まだ結果はなく、新しい手順を本採用していない。**

開始前に [手順と判定条件](protocol.json)、実際の担当指示、初期資料を固定し、[独立点検](protocol-audit-final.md)を行った。採用可能113枚と関連99枚、既知構築4件を含む同一の初期資料を両担当へ渡す。先行の自然試行で作った案や評価・調査は含めない。カードと構築内容は先行試行と同じで、来歴欄source:nullの明示が加わっている。

各方式は初回を含む最大3検討ラウンド。追加資料だけの調査も1ラウンドに数える。案のない終了、停止対継続の不一致、時間上限、形式再試行を保存する。初回の考案は25分を目安に新しい調査を止め、保存・形式修正に5分の猶予を設ける。評価は20分を目安とし、超過や未確認を隠さない。

工程、正確さ、発展、有用な出力、誠実さの5項目と、作業負担を分けて記録する。比較記録の充実や適切な停止だけで有用な出力を得たことにしない。担当差を含む1組であり、勝者・方式の優越・成功率を決める検査ではない。同じクラスを再利用する開発上の比較で、別入力への一般化と実戦の強さは未確認。

識別値と元の実行先は [manifest](manifest.json)。DB本体は含めず、初期の公開資料全文をgzipで保存する。既存のFAILや先行の自然試行の結果は上書きしない。
