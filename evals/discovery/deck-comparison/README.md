# 実リストからの交換枚数の計算

2026-09-08。公開CLIの `start → attach → compare → packet` で確認した。
入力は9/6に保存した[ナイフ案の比較リスト](../../../docs/rechecks/2026-09-06-knife-followup/decks.json)の
publishedとmixed。新しい構築の考案や推薦ではない。

種類別の枚数は変わらないが、ベルゼバブ1枚とマリオネットランサー1枚を抜き、リオナ2枚を入れる差を得た。
交換総数2枚と、フォロワー・スペル・アミュレットの純増減0枚を区別できている。
種類の内訳しか残っていない別資料を比較元へ渡すと、終了値2で拒否し、計算資料を追加しなかった。
同じ比較の再実行では同じ資料識別値となり、次のpacketへ計算結果が保存された。

`sources.json`が入力、`comparison.json`が計算結果、`verification.json`が照合結果、
`incomplete-error.txt`が不完全入力の応答。`manifest.json`で保存物を照合できる。
テスト用の別リストではスペル純増8枚・交換総数10枚も検査している。

元のWeb本文は今回再取得していない。能力・種類・コストは探索開始時のDB保存値であり、過去の能力へ復元していない。
この検査が示すのは交換の計算と証拠の受け渡しで、比較した構築の強さではない。
