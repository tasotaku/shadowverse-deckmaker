# 担当の終了を、手動更新を待たず進捗記録へ反映できた

探索システムの進捗を確認するユーザー向けの実装・検査記録です。担当が終了しても手動更新まで作業中に見える問題に対し、開始と終了を台帳へ直接保存する接続を実装しました。実際のAI担当の正常終了と、検査用の失敗・時間切れの3件で反映を確認したため、実行管理用として採用します。デッキ案の発見力を評価した検証ではありません。

開始を記録できたら担当を起動し、停止処理が終わってから工程を閉じます。監視中に台帳の書き込みを待って時間切れの検知を遅らせないよう、保存は起動前と停止後だけ行います。正常終了は工程完了、失敗・期限停止・起動失敗は工程中断です。提出の成否、有用性、採否、試行全体の完了は自動判定しません。

検査では、別工程の同時更新を保持すること、同じ工程の二重起動や訂正の上書きを拒否すること、台帳へ保存できなければ担当を起動しないことを確認しました。終了の反映だけ失敗した場合は、担当の結果を残してエラーを返し、担当を再実行せず記録だけを再反映できます。新しい20件と既存45件の自動テスト、型検査が合格しています。

実装中には、並行工程の保存順が開始順と逆だと時刻の整合検査に失敗する不具合を修正しました。また、全体の開始時刻が不明な古い試行では不明を維持します。保存自体は成功して応答だけ失敗した場合も、同じ工程を後から閉じられるようにしました。これらは実行するテストでも確認し、別担当の差分確認で指摘の解消を確認しました。

最後に、稼働中の本体台帳へ接続して実際のAI担当を起動しました。保存済みカード1枚を公開コマンドで読み、カード名・ID・コスト・能力要約を保存する仕事です。起動中の開始記録を確認した後、終了した3件について、親担当が台帳を書き直す前に状態と開始終了時刻を読みました。

| 実行 | 開始（2026年9月10日・日本時間） | 終了 | 経過 | 自動保存された状態 |
|---|---|---|---|---|
| 実際のAIによる公開読出し | 15:00:54.415 | 15:01:30.988 | 36.573秒 | 完了 |
| 意図的に終了番号7を返す検査 | 15:01:37.786 | 15:01:37.901 | 0.115秒 | 中断 |
| 1秒の制限を超えて待つ検査 | 15:01:37.786 | 15:01:38.798 | 1.012秒 | 中断 |

3件とも、台帳の開始終了時刻は実行記録と完全一致しました。終了から台帳保存までは約0.008〜0.023秒でした。後の2件の中断は意図した検査結果です。途中の出力も保存されています。実AIの公開読出しは1回で、カード情報の保存を確認しました。実対戦や新しい案の評価はしていません。

機能には台帳の指定を明示的に渡します。省略時は従来の実行監視として動きます。次の時間付き探索・評価を、この接続付きで起動します。画面の一覧は定期更新されますが、開いている詳細本文は「最新を表示」を押す既存の挙動です。担当の終了が保存されることと、表示中の本文を読み直す操作は区別してください。

監視プロセス自体の強制終了、PC停止、台帳障害中の即時反映は保証しません。子処理の停止を確認できない場合も、その不明を記録します。実装・検査を含む全工程の開始終了は[進捗画面](http://127.0.0.1:8765/#experiment/worker-journal-01)、検査条件と実測は[検査計画](test-plan.json)・[自動検査](test-verification.json)・[本体での確認](live-verification.json)に保存しました。
