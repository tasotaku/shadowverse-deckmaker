# 改訂と実施結果を読んだ別評価

2026-09-08。固定した2件は **2/2件PASS**。改善を認める判断と、確認済みの同じ問いを打ち切る判断を区別できた。
価値判断の指示文は厳しく変更していない。

| 入力 | 評価者が読んだ経緯 | 保存された判断 |
|---|---|---|
| a | 初版10PPで不足。軽減札に払う1PPも含めて9PP・13点へ改訂 | supported / test。実際にPP不足が解消したことを認めた |
| b | 全9枚と固定手札で最大8点と確認。その後も同じ13点の問いを言い換えた | refuted / drop。打切りをこの固定条件の枝へ限定した |

入力担当は、既知の[仮想カード](../role-chain/README.md)を再使用して初版と改訂を意図的に作った。
公開入口で2改訂と資料を保存し、初見の別担当がpacket内の履歴・本文・資料から評価した。
その後、別の採点担当が事前の条件・引用・因果関係・公開reportへの保存を照合した。

**自然な探索で改訂を思いついた実績ではない。** 先祖案と実施結果を渡したときの評価機能の検査であり、
未知入力・実カードの発見力・従来方式との差・勝率は未確認。以前の未達を取り消す結果でもない。

`expected.json`が事前条件、`evaluation.json`と`evaluation.md`が独立採点。
各a/bに初版・改訂・追加資料・検算結果・実際の評価と全文packetの可逆圧縮版を残している。
`manifest.json`で保存物を照合できる。SQL入力は元のrole-chainと同じ。
`prepare.py`と`create-sessions.py`は当時の入力作成記録で、固定された一時保存先を含む。運用入口は`svdeck.discovery`を使う。
