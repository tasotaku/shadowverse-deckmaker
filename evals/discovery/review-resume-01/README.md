# 保存済み正式案の別評価を再開する

**評価だけを再開する入口は実装できましたが、実AIは期限停止し、正式評価は0件でした。本採用は保留です。** 80件の機能検査、型検査、独立したコード点検は通りました。元の案を再生成せず、22資料と最新の正式案を別担当へ渡せた範囲まで確認しています。

## 何を直したか

前の比較試行では、通常構築と同じ状況で比べた追加側が、構成員を2枚から1枚へ減らす案と3資料を正式保存しました。しかし担当が提出後に終了せず、評価へ進みませんでした。そこで、保存済み最新案を指定して評価だけを実行する `--review-only --revision N` を追加しました。

元の案・資料・旧評価を準備先へ複製し、正式保存を再検査します。そこから評価資料を作り、評価担当には旧評価・旧入力資料版を除いたコピーを渡します。成功時だけ、新しい評価1件を元履歴付きの別保存先へ追加します。古い版・不正な指定・破損・未提出・時間切れは成功へ進めません。

## どう検証したか

1. 元の比較試行の失敗と正式案を固定しました。最新改訂2、22資料、親案1件と旧評価1件を保存し、判断基準も従来の5項目を維持しました。
2. 通常の考案→評価と、評価だけの実行を含む80検査を18.96秒で通過しました。最新版以外や不正な予算の拒否、履歴保持、旧評価の隔離、破損・未提出・期限停止を確認しています。公開CLIを模擬担当の別プロセスで実行する検査も含みます。
3. 実AIの別担当を、経過時計の上限600秒・再試行なしで1回起動しました。公開読出し16件は成功しましたが、正式評価と提出用の評価ファイルは残りませんでした。期限で停止し、終了結果は `review_failed` です。
4. 元の33ファイル、正式案の内容、カードDB、凍結した実装が不変であることを照合しました。元の比較試行の失敗も、そのまま保持しています。

## 結果と次の作業

**機能検査の合格と、実AIの評価完了は別です。** 実AIでの完了が未達なので、再開補助の本採用も保留します。「同じ状況で通常構築と比較する」方法の追加側は、依然として評価未完です。案が弱いという判定や、比較方法が優れているという判定は出していません。

今回も時計差が大きく開きました。評価の日本時間は9月10日23:02:51〜23:52:12で、49分20秒です。一方、実行監視の経過時計は600.062秒でした。差は39分20秒あり、10分で利用者に結果が届いたとは言えません。応答ストリームの切断・再試行を示す警告も1件ありましたが、その後、PCの記録で23:07:05の自動スリープと23:48:03までの複数のスリープを確認しました。記録上のスリープ計39分28秒は時計差に近く、主因と考えられます。ただし通信切断や未提出の全因果は未確定です。

次はOS標準の `caffeinate -i` を使い、担当を実行する間だけ自動スリープを抑えます。実行中の抑止要求と終了後の解除を確認したうえで、同じ保存案の別評価を新しい試行として行います。案・評価指示・10分の監視上限は維持します。
