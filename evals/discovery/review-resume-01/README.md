# 保存済み案の別評価を再開する

案を作り直さず、正式保存済みの最新案を別担当へ評価だけ渡す入口を実装した。機能検査80件と型検査は通過し、これから実AIで1回・上限10分の別評価を行う。案の有用性はまだ未評価。

元の比較試行では案1件と追加資料3件を正式保存できたが、提出後に担当が終了せず15分で停止し、評価へ進まなかった。その原因は未確定。元の停止・評価0件はそのまま残す。今回の追加時間と結果を別に記録する。

元の22資料・正式案2版・旧評価1件を複製し、最新改訂2の保存形式を再検査する。準備先で評価資料を作り、担当用には旧評価を除いた資料を渡す。正式評価1件だけを新しい保存先へ集約し、元の保存先を書き換えない。

検証前に固定した手順と条件は protocol.json、正常・境界・失敗の検査結果は preflight.json、入力の独立点検は recovery-audit.json に保存した。画面では各工程の開始・終了日時を確認できる。
