# 利用上限で止まった2案の評価を、同じ入力から再開する

探索システムの開発を依頼したユーザーが、評価の現在地と所要時間を確認するための報告です。採用負担を減らす改訂で得た2案を、別担当が評価中です。両担当は2026年9月10日14時25分23秒（日本時間）に開始しました。有用性と、改訂指示の本採用は未判断です。9月10日14時33分時点の記録です。

[元の比較](../burden-revision-01/README.md)では、従来版と、配分・使い方の変更を優先する版が、それぞれ改訂案1件を保存しました。その後の評価は両方とも利用上限で終了し、新しい正式評価は0件でした。利用可能に戻ったことを確認し、同じ評価入力から新しい別担当が評価を始めています。考案はやり直していません。

入力には、各方式が提出した案、カード本文、保存された調査資料を渡します。元の評価開始時点と全ファイルの内容が一致することを確認しました。未提出の評価下書きや、別担当が途中で出した評価は渡しません。各担当は上限15分で1回実施し、カード手順の成立、通常構築との差、採用で失う役割、核を引かない場合、既出調査の限界から、試す理由があるかを判定します。40枚完成・20点確定・勝率証明は求めません。

評価終了後は、公開コマンドへの正式提出、保存された評価、結果画面の一致を確認します。元の改訂内容と合わせて、有用な案へ進んだか、本採用の根拠になるかを記録します。再び実行が失敗した場合は途中出力を残し、未判定のままとします。元の試行を、途切れず成功した実行へ書き換えることはありません。

既知のビショップ案1件を再利用した比較です。良い結果が出ても、新しい入力での発見力や方法の一般的な優位をこの1件で認定しません。工程の開始・終了日時と現在地は[進捗画面の詳細](http://127.0.0.1:8765/#experiment/burden-review-recovery-01)、固定条件は[検証条件](protocol.json)で確認できます。
