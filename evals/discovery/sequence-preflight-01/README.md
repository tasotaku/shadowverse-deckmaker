# 提出前に行動順を点検する方法の比較

**現行・変更版の両方式が考案中です。方法の採否と案の評価は未判定です。** 前の比較では、通常構築の別手順と自案で避けられる損失が、別評価まで見落とされました。今回はウィッチの初回探索で、提出前の点検が役立つかを比べます。

同じ保存DBから作った資料を現行A・変更Bへ渡します。Bだけ、仮の比較を一度保存してから、同じ手札・PP・盤面で行動順を変える点検を一回行います。見つかった違いを比較と判断へ戻し、元の記録も残す指示です。個別のカードや正解は指定していません。考案20分・別評価10分を各一度とし、未提出・未評価で終わった場合も記録します。

点検結果が実際の判断を改善し、別評価でも支持されるかを見ます。記入欄や資料の増加、反例が見つからなかったことだけでは合格にしません。現行と同じ結果なら採用保留です。両方式で選ぶ案が違う可能性もあり、各一度では担当の違いや一般的な発見力は切り分けられません。

新しい初回探索入力ですが、最新環境を取得した比較ではありません。保存資料の取得時点を維持し、現在の普及や勝率は未確認として扱います。[開始前の固定条件](protocol.json)、[固定入力一式](input-session.tar.gz)、[進捗と工程時刻](http://127.0.0.1:8765/#experiment/sequence-preflight-01)。
