# 参考記事の採否理由を引き継いで考案する

**指示を隔離した実装で試作し、機能検査118件と型検査に合格しました。実AIでの比較結果と方法の採否は未判断です。**

参考記事が対象札の採否を論じている場合、その理由・短い原文抜粋・判断が成り立つ構築や対面や時期・今回との一致と相違を、既存の資料保存へ残して考案に使う指示を追加しました。個人の不採用を全構築の却下条件にはしません。通常版と変更版では考案指示だけを変え、カード・注記・参考資料・回答形式・別評価の基準を揃えています。

入力はビショップ／ローテーションです。今回取得した進化ビショップの40枚と取得情報、9月の記事説明と6月の使用者インタビューの限定要約を同じように渡します。初期要約は開発担当が作成しており、原文の自動取得能力やゼロからの要約能力を比較する試験ではありません。6月の個人構築を現在の標準として扱わないことも確認します。

手順は、指示の試作→機能検査→同一入力の照合→両方式が各30分以内で考案・保存・提出→正式案があれば各15分以内で別担当が評価→採否と時間の記録、です。各方式は考案・評価を1回ずつとし、途中の入力修正も記録します。未提出なら開発担当が代理提出することはありません。

確認するのは、記事の理由が案の比較に使われたか、元の条件と今回の条件を区別したか、最終的に試す理由のある種が残ったかです。元資料を直接参照して同じ判断ができた通常版も同等に数えます。追加保存の件数だけで変更版を有利にしません。機能検査の合格も、発見力の証明には数えません。

開始終了時刻は工程ごとに記録画面へ反映します。過去に開発で扱ったカードを含み、この結果だけで全般的な優位やシステム完成とはしません。変更版の有用な種が0件なら本採用せず、同数なら発見力は同点と扱います。
