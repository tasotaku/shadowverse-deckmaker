**終了直後の確認を最大0.2秒だけ再試行する修正を入れました。** 実際のAI処理では、修正前は主処理の終了後も確認の権限エラーになり、修正後はプロセス群の消滅を確認して期限停止として記録できました。

一問調査の2実行で、10分後の停止要求により主処理は終了しましたが、直後のプロセス群の確認が権限エラーになりました。後の確認ではどちらの群も存在しませんでした。親の終了を回収してからすぐ再確認するだけでは不足する場合がある、という観測です。OS内部の原因は特定していません。

権限エラーの場合に限り、50ミリ秒の間隔で最大5回確認します。存在しないという応答を受けた場合だけ消滅と扱い、拒否が続けばエラーを残します。権限エラーそのものを「停止できた」と読み替える変更ではありません。

| 確認 | 結果 |
|---|---|
| 子処理12個を持つPythonで修正前を4回実行 | 全て期限停止。今回の不具合は再現せず。 |
| 実AIを10秒で止める・修正前 | 約10.015秒。主処理はSIGTERM終了、群の確認に権限エラー。終了コード125。 |
| 同じ指示と実行条件・修正後 | 約10.064秒。期限停止と群の消滅を確認。終了コード124。 |
| 関連検査 | 新規2件を含む20件に合格。型検査も合格。 |

検査は、一時的な確認拒否から消滅へ変わる場合と、拒否が続く場合の両方を含みます。[検査の範囲と限界](verification.json)、[実AIの修正前](before-ai/run.json)・[修正後](after-ai/run.json)、[停止後の確認](post-stop-check.json)に実時刻を残しています。内部の思考を含むAIの実行ストリームは収録しません。

短い実AI処理各1回で確認した実行管理の修正です。長い終了遅延や永続的な権限拒否を解決したとはしていません。探索の有用性の証拠には数えず、一問調査の失敗した終了コードや保存結果を後から書き換えてもいません。
