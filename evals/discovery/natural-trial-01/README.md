# 主役を指定しない自然試行1

ローテーションのエルフを対象に、公開入口から着想・資料追加・提出・別評価・必要な改訂を行う試行。
初回提案を受け取る前に、[手順と判定条件](protocol.json)と入力を固定した。**現在は実行中で、合格や有用性を認定していない。**

初回は提出と独立評価まで完了し、評価は conditional / develop / unconfirmed。
8枚補充の利益と6枚交換で失う役割を比較する必要が残り、試行を勧めるtestには届かなかった。
当時の案、追加9資料、実際の回答と操作上の問題を [初回の保存記録](round-1/manifest.json) にまとめた。
次の段階では実際の評価を返し、追加比較と改訂または打切りを進めている。最終の5項目採点は未実施。

実利用中に見つけた資料の参照位置と外部調査の回答形式の説明不足を修正した。
途中の本体変更、確認範囲、未確認点は [変更記録](system-changes.json) にある。
初回の評価記録は修正前の回答例で2回失敗した経過を保持し、1回で通った結果へ置き換えない。

採用可能な113枚と関連99枚、ユーザー注記、ルール、同クラスの公開構築4件を入力にした。
カードはローカル保存版。構築資料は当日取得し、全40枚と対応を確認した範囲を [QA記録](inputs/source-qa.json) に残す。
取得した全65記事には別クラスの不完全リストがあり、全件取得が正しかったとは扱わない。

工程が動いたか、最終手順が正しいか、調査で判断が進んだか、試す理由のある種が残ったかを分けて評価する。
最大3提出の一試行であり、方式の優越・全範囲の発見力・実戦の強さは示せない。過去のFAILは保持する。

`initial-packet.json.gz` は初回の公開資料全文、`initial-cli-*.json` は開始・資料追加・要約出力。
入力の識別値と元の実行先は `input-manifest.json` にある。DB本体は同梱しない。
