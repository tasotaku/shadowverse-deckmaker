# 主役を指定しない自然試行1

ローテーションのエルフを対象に、公開入口から着想・資料追加・提出・別評価・必要な改訂を行う試行。
初回提案を受け取る前に、[手順と判定条件](protocol.json)と入力を固定した。**試行は完了。有用性はFAILで、試す理由のある種は得られなかった。方式の本採用は保留。**

[最終採点](final-evaluation/evaluation.md)は、工程PASS（途中修正を含む）、正しさ未確認、発展PASS、有用性FAIL、誠実な説明PASS。提案本文Bに旧誤記が残り、訂正を添付資料から読む必要がある。総合点を作らず、調査の進歩と有用な種の獲得を分けた。[本採用を保留した理由](method-decision.json)も保存し、開発全体は次の方式検証へ続ける。

初回は提出と独立評価まで完了し、評価は conditional / develop / unconfirmed。
8枚補充の利益と6枚交換で失う役割を比較する必要が残り、試行を勧めるtestには届かなかった。
当時の案、追加9資料、実際の回答と操作上の問題を [初回の保存記録](round-1/manifest.json) にまとめた。
追加段階では全40枚を用いた6枚・1枚・3枚交換の比較、指定局面2件、9条件の取得率を調べた。
提案担当は元の6枚変更の枝を止めたが、独立評価2は conditional / develop / unconfirmed。
補充して生存できる例の終了盤面と次ターンの接続が未比較で、停止根拠がまだ足りないという評価だった。
両者の判断を [追加比較の保存記録](round-2/manifest.json) に残し、実際の評価を提案担当へ返した。
次の段階では終了盤面を訂正し、全23枚の残り山札と共通札の順序を揃えた指定引き順3組をT9まで比較した。
両側それぞれが先に決着する組が見つかり、提案担当は停止理由を撤回してrevision2を提出した。
[3段目の保存記録](round-3/manifest.json) はこの比較と改訂を保持する。独立評価3もconditional / develop / unconfirmedで、試す理由はまだ不足。相手が除去順を変えるとバリア付きルリアが残り、示した5枚展開を使えないという指摘を受けた。
[4段目の追加比較](round-4/manifest.json)では、同じ手札から14点・相手盤面全処理の別手順を確認した。ただし少数補充案でも再現でき、6枠全体の負担を正当化する根拠は増えなかったため、提案担当は原6枚配分の検討を限定停止した。全用法が不可能とは判断せず、追加提出はしていない（正式提出は計2回）。独立評価4はconditional / develop / unconfirmed。全6枠の推薦は認めない一方で、補充役を確実に検索できる差が残るとして仮説を継続対象にした。具体的配分の停止と仮説全体の継続という対象範囲の違いも保存した。上限3提出のうち1枠は未使用で、数を埋めるだけの改訂は要求していない。
指定した局面と引き順の比較であり、そこへの到達頻度、全6枠の必要性、実戦の強さは未確認。

実利用中に見つけた資料の参照位置と外部調査の回答形式の説明不足を修正した。
途中の本体変更、確認範囲、未確認点は [変更記録](system-changes.json) にある。
初回の評価記録は修正前の回答例で2回失敗した経過を保持し、1回で通った結果へ置き換えない。
評価2は修正後の回答例で1回で登録できた。担当と回答も異なるため、例の追加だけによる改善とは確定しない。

採用可能な113枚と関連99枚、ユーザー注記、ルール、同クラスの公開構築4件を入力にした。
カードはローカル保存版。構築資料は当日取得し、全40枚と対応を確認した範囲を [QA記録](inputs/source-qa.json) に残す。
取得した全65記事には別クラスの不完全リストがあり、全件取得が正しかったとは扱わない。

工程が動いたか、最終手順が正しいか、調査で判断が進んだか、試す理由のある種が残ったかを分けて評価する。
最大3提出の一試行であり、方式の優越・全範囲の発見力・実戦の強さは示せない。過去のFAILは保持する。

`initial-packet.json.gz` は初回の公開資料全文、`initial-cli-*.json` は開始・資料追加・要約出力。
