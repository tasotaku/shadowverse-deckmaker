# 提出確認まで含めて進捗を自動記録する

**実行補助として採用しました。担当の終了と、最後の提出確認の成否を別工程で自動記録できます。本体の公開操作から、成功・提出確認失敗の両方が「結果・採否の確認待ち」になることを既存の進捗画面のデータで確認しました。**

前は担当が正常終了しても、後の提出確認に失敗すると、試験全体が実行中のまま残りました。任意の事前登録工程を使い、調査・照合から最後の提出確認までの開始・終了・停止理由を記録します。結果の評価や採否は自動変更しません。他の担当が動いている時や、停止を確認できない時には確認待ちへ移しません。手動訂正も保持します。

## 検証手順と採用理由

1. 実行原本2件で、担当終了と提出確認失敗が別だったのに、全体表示へ後者が戻っていないことを確認しました。
2. 設計を記録してから別の作業場所で実装しました。任意指定をしない既存の呼出しは維持しています。
3. 新規24件と既存62件の計86件、3ファイルの型検査を実行しました。正常提出・未提出・提出確認失敗・異常終了・期限・同工程への訂正・別工程の並行・終了済みの記録を確認し、全件合格しました。
4. 本体へ反映して実装の一致を確認し、人工資料と偽の担当を使って公開コマンドを2回実行しました。正常提出では全体工程が完了、意図的に最終確認を欠いた場合は全体工程が中断となり、担当が正常終了したことと区別できました。
5. 各実行直後に、既存の http://127.0.0.1:8765/ の個別データを読みました。開始・終了が実行記録と一致し、全体は確認待ち、結果と採否は元のままです。元の実AIの失敗は変更していません。

採用理由は、提出確認で止まった結果を手動回収前に判別でき、実行時刻と採否の確認を分けられたことです。これは動作検査の成功で、人工資料の内容や新しいデッキ探索手法が有用だと認めたものではありません。実AIによる新経路の全実行は未確認です。

## 次に使う時
