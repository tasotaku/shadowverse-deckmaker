## 実装するなら最小の形

新しい探索器を作る前に、既存の`packet`へ任意の`--effects CARD_ID ...`を加える案が最小です。これは未実装の提案です。

1. 既存SESSIONの固定DBから、選んだ数枚の本文・注記・現行検索タグ・保存分解効果・別形式の保存効果をまとめる。本番DBの別時点の値を混ぜない。
2. 保存分析には「未検証の下書き」と抽出時点を付ける。AIは原文の引用から、変化と発動条件を結び直す。差分の自動合計や機械的な成立認定はしない。
3. AIは通常の役割という仮定、条件付きの別用途の問い、条件を外した対照、未確認点を返す。既存の`hypothesis/steps/uncertainties/questions`へ置き、検索・別評価へつなぐ。該当なしも認める。

通常のpacketや現在進行中の比較入力は変えず、追加を選んだ新資料だけ別の識別値で保存します。既存の本文だけの入口にも副作用を考える指示があるため、この追加が有益かは未確定です。

自動計算へ進む前には、少なくとも「各差分と原文の効果・条件との接続」「選択・追加・置換・時点」「生成と移動・墓場と破壊履歴の区別」「使用前後の数え方と支出」「本文の版」が必要です。全カードの作り直しを先に始める理由は、この調査では得られていません。

## 問いの例（合計3件、1件は条件を外した対照）

1. **カオティックカースのドロー側。** 山札20枚のうちフォロワー2枚、指定ドローが正常に1枚行われた状態では19枚中1枚へ変わる。「手札補充に加え、山札のフォロワーを減らす用途なら、その少なさを利点にする効果はあるか。特定の1種類を残すなら何の制御が足りないか」。このカードには密度操作タグが既にあり、例示自体を新発見とは数えない。
2. **同じ条件からドロー側の選択を外し、リアニメイト側を選ぶ。** 山札減少の結論と同じ問いを引き継がない。保存差分をそのまま使えば誤る対照になる。
3. **ルルミが今破壊され、手札に空きがある。** 手札はバット1枚分増え、山札は減らない。「得た手札を直接プレイ以外の支払いに回すなら、受け手は何を素材にできる必要があるか。そのための破壊手段は必要か」。破壊前からの純増やバットの後続行動は数えない。受け手は未探索。

いずれも本文から作った条件付きの問いで、デッキの強さ、新規性、実用案の獲得を認定しません。

## 次の別試行

既存の比較は変更しません。次の開発確認では、上の3ケースを固定して、A=現在の本文中心資料、B=同じ資料に選択カードの未検証分析を添えたものを、同じモデル・時間上限・外部検索条件で比べます。上の例を教材にした確認なので未知評価とは呼びません。

出力は各ケースで「引用・状態変化・問い0〜1件・未確認点・実際の追加検索1件か検索不要の理由」。確認するのは、条件を落とさないこと、対照で誤る用途を出さないこと、問いが単なるタグの言い換えを超えて次の検索へ進むことです。時間・読む量・条件誤りも併記します。説明項目が増えただけなら改善に数えません。既知3件で良くても、未知入力の発見力と元の評価基準による採用価値は別途必要です。
