## 何が分かり、なぜ保留にしたか

入口ありでは検索を1回使い、問い・23候補・残った問題を追加資料へ保存できました。ただし選んだ札も競合する札も検索前に本文を取得していました。読み取り操作が内容を返したことと、その場で理解・着想したことは区別し、検索による初発見とは認定しません。

入口なしは、墓場を先に増やして進化権を温存する使い方に発展しました。入口ありは、自分の札を壊した後の交代を早め、手札補充と同じターンの墓場不足へつなぎました。双方とも1枠交換ですが、失う通常札の役割と準備の負担に見合う利益は示せず、追加検討です。

入口ありの案では、同じ1枠に入れられる有力な既知代案が資料と検索結果にあるのに、提案担当の比較から抜けていました。これを比較へ戻したのは別評価です。その寄与を提案担当の発見や検索の効果には加算しません。検索補助を撤回する根拠もありませんが、各1回・試用推薦0対0から発見力の改善を追加認定することもできません。

## 次に変えて試すこと

現行の指示は指定された通常構築で取れる行動を比べるものです。資料内の「同じ変更枠で競合する代案」まで明示していない点をコードで確認しました。これを原因と断定せず、[短い比較案内を加える次の検証](../same-slot-alternative-01/README.md)へつなぎます。検索機能や回答形式を増やす試験ではありません。

次は同じ保存済みの仮案を、後の別評価を渡さずに改訂します。改訂15分・別評価10分を各一度。比較欄の充足や弱い案の棄却だけで成功とはせず、配分や用途の変更から試す理由が残るかを見ます。旧案を使う試験であり、新しい初見入力とは呼びません。

## 比べた方法と開始前の判断基準

考案中に不足が見つかったとき、その場で新しい条件をカードの効果から検索できる入口が、案の発展と試す理由につながるかを調べます。検索補助そのものの採用は前の[実利用検証](../live-query-01/README.md)で確認しましたが、そこで候補は検索前にも読まれており、発見力の向上は示せていません。

この試験はナイトメア・ローテーションの新規入力です。保存DBから選んだ全8記事URLを固定し、カード本文・双方の注記・記事・一般方針を同一版で渡しました。このクラスや全カードが初見という意味ではありません。開発者は具体カード・検索条件・期待する案を指定していません。

両方式の違いは、未提出の新しい条件を検索する操作とその案内です。検索の使用は強制しません。上限は考案20分、別評価10分を各一度。追加の自動改訂や、時間切れ後の考案やり直しはしません。既存の終了操作で、正式保存を確認してから次へ渡します。

検索回数や候補数を成果にせず、通常構築と同じ状態から比べて、どの不足が解決し、試す理由が残ったかを確認します。検索前から読んでいた候補や、評価者が後から足した手順も区別します。試用推薦・独自性・手順成立は別々に判断し、一回ずつの差で一般的な効果を断定しません。独自性の新しい問いが残る試用候補には、両方式で同じ条件の先例調査を一度接続する条件でした。今回は対象0件のため先例調査を行っていません。勝率・Tierは評価しません。
