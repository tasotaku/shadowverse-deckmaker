# 二案のPP比較の試作仕様

状態：隔離した場所で実装する任意の計算補助。本体取り込み・方式の本採用は未判断。

## 解く問題と範囲

idea-comparison-01では通常案に未使用の追加PPが残ることを見落とし、現在PPの差2と利用可能なPPの差1を取り違えた。class-choice-01の初回調査でも、7PPでは5＋3を払えないことを停止の理由としたが、後攻で残した追加PPがあれば支払える場合が残っていた。

開始状態と行動順に明示されたPP増減を二案について計算し、未使用の追加PPを自動で引き継ぐ。原文からカードの効果や条件を推測する仕組みではない。現在PPと追加分を別々に返し、元の手順にない追加PP使用を勝手に実行したことにしない。正しい手札・盤面・効果条件・進化権や強さの保証には使わない。

## 公開入口と保存

既存の `python -m svdeck.discovery` に任意の `pp SESSION INPUT.json` を加える。入力は二つの計画と、その入力を支える既存の資料の識別値を持つ。結果は既存の `save_sources` を用いてsessionへ追記し、packet/read/reportで参照できる。既存の開始・提出・compare・資料形式は変えない。主な実装は `discovery_resources.py` 1個とCLI接続。

入力例の形（最終的な欄名をREADMEへ揃える）：

```json
{
  "source_hashes": [],
  "plans": [
    {
      "name": "複製を使う",
      "side": "second",
      "start": {"turn": 6, "pp": 6, "extra_pp": "available"},
      "actions": [
        {"kind": "use_extra", "label": "後半の追加PPを使用"},
        {"kind": "pay", "amount": 5, "label": "支払い"}
      ]
    },
    {
      "name": "通常の手順",
      "side": "second",
      "start": {"turn": 6, "pp": 6, "extra_pp": "available"},
      "actions": [
        {"kind": "pay", "amount": 6, "label": "支払い"}
      ]
    }
  ]
}
```

この人工例の終点は現在PPが2対0、使える追加分込みでは2対1。差2と差1を区別する。正解を知った転記だけで有用性が示されたとはしない。

## 計算規則

- 二計画の `side` は `first` / `second`。開始turnは1以上、開始ppは非負の整数。現在PPは最大値ではない。開始状態の根拠が省略された場合も、ゼロ資料の申告として明示する。
- `extra_pp` は `available` / `used` / `unknown`。先攻に使用可能な追加PPを設定しない。不明を利用可能と推測しない。
- `pay` は明示した消費、`gain` は上限処理や発動条件を外部で確認した後の実際の増加量を受け取る。印刷値から回復上限を推測しない。負の値やboolを整数として受け入れない。gainの真実性・カード効果はこの道具の保証外と常に表示する。
- `use_extra` は後攻の未使用分だけを+1へ変換し、使用済みにする。先攻・再使用は不正な手順として残す。不明の場合は未確認の手順として止め、仮に使えたことにしない。
- `next_turn` は次の連続する自分ターンと、その開始時のppを明示する。ppは持ち越さない。追加分の使用状況は保持し、後攻のT5→T6だけ使用可能へ戻す。未使用の前半分を後半に2回使える形へ累積しない。省略されたターンの資源消費を勝手に仮定しないため、飛び越したターンは受け取らない。
- 支払いが現在PPを超えると、その前までの計算と不足を返す。残った追加PPでちょうど補える場合は「追加PPを使う操作が必要」と返し、単純な不成立・無価値へまとめない。不明な追加分で補える可能性しかない場合は未確認。追加分を含めても足りない場合でも、その宣言手順のPP不足に限る結果であり、全カードによる不可能の証明ではない。
- 手順の途中で問題が起きたら、それ以降の終点を計算したことにしない。二案の同じ先後・同じターン・完了した終点についてだけ現在PP差と追加分込みの差を返す。追加分が不明なら込みの差を確定値にせず、範囲または未確認とする。
- 入力に残量の自己申告を任意に持たせるなら、計算結果との差を示す。少なくとも計算値と自分で記した説明を利用者が照合できる各行の前後値を返す。

追加PPの基準は固定docs/rules.md。公式ヘルプの検索取得でも、後攻のみでターン中の消費可能PPを1増やし、T6開始時に使用済みなら再使用可能となる説明を確認した（2026-09-09）。通常openは外枠のみで、動的本文の直接取得は未確認。上限を含むPP回復の詳細へ勝手に一般化しない。

## 検査と採用の境界

機械検査では、差2と差1、後半に温存した1PP、前半使用後のT6再使用、前半未使用でも後半2回は不可、先攻、追加分不明、負残量、支払途中の失敗、ターン更新、gainの宣言量、入力と資料の同一性、保存版からの読出しを確認する。mypyと関連tests、人工DBの公開入口で実行する。

次の実利用確認では、過去の訂正前の資料を固定して別担当が入力化し、既存の自由な計算と新操作の結果・見落とし・総時間を比べる。正解を知らせた写経、全体シミュレータへの肥大化、同精度で負担増だけなら採用しない。class-choice-01へこの新実装を途中投入しない。検査合格だけで発見力の改善や全体目標の達成とはしない。
