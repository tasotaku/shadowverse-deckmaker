# 相手の返しを受けた後の利益を比較する

**相手資料を渡す機能は採用し、採否を判断する方法の本採用は保留します。** 既知の2例を各1回評価した結果、どちらも「追加検討」でした。固定していた依頼者の判断との一致は0/2で、良い案・悪い案を見分ける改善は示せていません。開発は次の修正へ続けます。

| 比較した案 | 固定した依頼者の判断 | 今回のAI判断 | 分かったこと |
|---|---|---|---|
| マゼルで後半を補充し、序盤へ配分を寄せる | 組んで試す候補 | 追加検討 | 補充は読めているが、試用前に具体的な枠差を要求。比較した相手ターンはマゼル発動前で、補充後に相手の返しを受けて札を使う利益は未検証。 |
| ナイフ潜伏とリオナを使う2枠変更 | 見送り | 追加検討 | 2種類の返しで、翌ターン打点が5または10、通常側は20となる条件付き比較を保存。本人の見送りの決め手と同じ理由かは未確認。 |

手順は、相手の合法な40枚・カード本文・注記を固定DBから追加し、相手の同じ手札と行動を提案と通常側へ当て、残る利益と失う用途を比べるものです。異なる準備ターンによるPP差は維持しました。元の出題と期待判断を保持し、相手資料1件と比較指示6文を追加しました。各1回・上限10分で正式評価を回収し、別担当が選んだ4種類の返しを照合しました。

通常側は、マゼルでは補充役をミロクへ替えた同じ開始状態、ナイフではベルゼバブ3枚・リオナ1枚の保存構築です。

相手資料は7月末取得の連携ロイヤルです。手札・先行するプレイ履歴・盤面は明示した仮定で、引ける頻度や現在の環境を代表する証拠はありません。4種類の検算は最善手や全対戦の再現ではありません。ナイフの独自性判定には、内部で過去に試した事実を「一般に広まっている」という基準と取り違えた問題も残りました。保存された旧判断は変更しません。

機能は `python -m svdeck.discovery opponents SESSION --deck-id ID` で使え、`--preview` は表示だけです。40枚・同名上限・クラス・合法性・欠損を検査し、本文と関連カード・注記を追加資料へ保存します。修正後の53件と型検査は合格。実評価で使った2資料は修正版の出力と全文一致し、元DB・旧入力は保持しています。資料を渡す補助の採用を、探索方法全体の有用性へ広げません。

次は、主張する利益が得られる時点まで検証が進んでいるかを揃えます。その前に、通常の新規探索へ実験の正解・採点履歴が混ざる読み込みを修正し、新規入力で履歴の除外と必要な原則・注記の保持を確認します。今回の2例は凍結済みの旧入力を使っており、その修正で再採点しません。
