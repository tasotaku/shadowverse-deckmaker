# 既知の案を推薦・保留へ戻さないかの検査

2026-09-08の固定条件では **FAIL、採否一致1/2件**。
ナイフ2体21点型は見送りになったが、イマリ17枚型は追加調査に残った。条件付きの成立計算と推薦は区別され、2件とも試行推薦には上がっていない。ただし、今回の基準は両方を見送ることであり、推薦が0件だっただけで合格にはしない。

入力担当が既存の記録から案を再構成し、公開入口へ未評価の初版として登録した。
別担当は固定した資料と案だけを読み、正解・実装・過去の調査報告・他担当の評価を見ずに評価を保存した。
主役と相方双方の注記は削っていない。これは既知のフィードバックを反映する検査で、未知の発見力の検査ではない。

原因はまだ一つに確定していない。

- 入力：比較元の旧40枚が保存資料にない。9/7の具体的な序盤・対面の経験も再構成時に薄まった。
- 判定：既に残っていた不足を「比較すれば変わりうる」と再度問うだけで、今の17枚型へ調査を足す根拠になっていた。

次は、比較に使う資料と出典を丸ごと固定できる入口を加え、入力不足と継続判断の甘さを別々に試す。
直接打点0、条件が多い、未実戦というだけで一律に切る規則にはしない。
型別の純増8枚は、実際に入れ替えた札が8枚ずつだったことを意味しない。旧40枚を推測して補わない。

`expected.json` が事前基準、`evaluation.json` / `evaluation.md` が正式採点。
`proposal-*.json` / `review-*.json` は提出物、`packet-*.json.gz` は実際の全文資料を可逆圧縮したもの。
`manifest.json` は保存物の識別値。資料内の `/tmp` のパスは当時の実行記録である。

資料はPythonで読める。

```python
from pathlib import Path
import gzip
import json

path = Path("evals/discovery/known-candidate-review/packet-imari.json.gz")
packet = json.loads(gzip.decompress(path.read_bytes()))
print(packet["sha256"])
print(packet["data"]["proposal"])
```

この結果を用いて実装を直した後の再試験は、同じ開発用事例の再検査であり、新しい未知評価とは数えない。
