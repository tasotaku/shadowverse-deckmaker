# 残った問いの調査と別担当への引渡しをつなぐ

**調査報告と追加資料4件は保存できましたが、引渡し処理に不具合があり、別担当の照合は起動できませんでした。実行補助の採用は保留です。**

保存済みの評価から問いを指定し、調査→資料保存と本文の再読→別担当による根拠照合を一度の実行でつなぐ入口を試しました。案の再改訂や旧評価の上書きは要求せず、資料保存と問いの解決を分けます。初回はナイトメア評価に残った「このクレストで監獄を破壊する用途が公開構築・解説に広まっているか」という問いです。調査15分・照合10分を各1回に固定しました。

## 実施した手順と結果

1. 資料読出し・attach-file・元ファイル保持・workerによる期限管理を再利用して実行入口を実装しました。関連139検査・型検査と別点検を通過しました。
2. 実際の調査担当は8分08秒で終了し、実検索語と返却URL、短い本文抜粋と観察・解釈、元入力の参照抜粋、結論報告の4資料を正式保存しました。公開操作は20件、各操作の終了番号はすべて正常でした。
3. 担当は保存後に新しい資料版の報告全文を再読し、reportも実行しました。しかし親側の引渡し検査が、途中のattach-file --helpの説明文をJSONとして解析し、Expecting valueというエラーで停止しました。
4. 元入力14ファイル、本体カードDB、実行コードと保存資料を保持し、正式改訂0件・新しい正式評価0件、別照合0回の失敗として回収しました。

先にreport --helpだけで確認済みになる別の見逃しを修正しましたが、添付ヘルプを解析対象にしてしまう問題は検査に含まれていませんでした。担当の未提出や資料の否定材料による停止ではなく、実行側の応答処理の不具合です。

## 調査で得たことと限界

保存報告には、クレストでアズヴォルトを破壊する機構が公開解説にあり、元のミッドレンジ記事でも入れ替え候補として説明されている、という発見があります。カードの同居だけを見るリストでは落ちていた情報です。ただし、この試行では別担当の照合を行えていません。一般的な採用率や、元案の1枚交換と限定運用そのものの普及も未確認です。

**資料保存は確認できても、調査から独立した根拠照合まで完走していないため採用保留**です。139検査の合格や4資料の増加を、方法全体の有用性の証明にはしません。元案の強さ・独自性の正式評価も変更していません。

次は[ヘルプの扱いを修正する試行](../inquiry-help-01/README.md)です。保存済み本文・公開操作を変えずに検査し、未起動だった照合だけを別の実行で行います。この失敗を成功へ遡及せず、調査を繰り返しません。
