## 何が変わり、なぜ保留にしたか

両方式とも、複数の札と墓場を必要とする旧案を見送り、単独で補充と処理を担う記事既載の候補へ1枠を変更しました。同じ手札・盤面から通常側の手順まで比較し、増える補充と残る盤面、失う序盤の札や守護を配分判断へ戻しています。説明を増やしただけでなく、採用候補と用途の変更は確認できました。

ただし、この変更は追加指示のない現行も自力で行っています。代案選択と配分変更は双方の提案担当が別評価前に行ったもので、別評価が初めて教えた答えではありません。試用推薦1対1や少しの時間差を、追加文の効果にしません。

別評価は、序盤・重い札の配分負担を枚数で補い、旧案の数値を「提案側」と呼んだまま残す比較資料の表記も指摘しました。正式な新案の終点計算とは区別し、原資料を黙って修正せず残しています。表記訂正だけを発見力の改善とは扱いません。

保存記事には同じ基盤・交換元・処理と補充の役割が載っています。今回の具体的な検算や1枚配分を新発見とは認定しません。一方、一つの記事にあることから広い普及を推定して候補を自動棄却することもしていません。普及度の追加調査、最適枚数、実戦成績は未確認です。

## 次に確認すること

現行も別の使用時点や失う役割について問いを作れており、一般的な別用途の指示を足すだけでは差分にならないと点検しました。次は[既知案への変更後に残った問いを比較へ移す再検証](../remaining-question-01/README.md)を行います。過去の「不足を比較へ戻す」手順と重なるため新方式とは呼ばず、試用可・既知という変更後の未比較の問い一件を対象にします。追加指示は隔離して試作中で、今回の指示を本体採用したわけではありません。

## 比べた方法

前の[検索入口の比較](../live-query-discovery-01/README.md)では、有力な代案が記事と検索結果にあっても提案担当の比較から抜け、別評価で初めて比較へ戻りました。この試験では、同じ採用枠に入る代案も比べ、その差を採用枚数や使い方へ反映する短い案内を加えます。

例えば、特別な組合せのために通常札を1枚減らすなら、その1枠を別の既知候補に替えた場合とも、同じ手札・盤面から比べます。具体的にどの札を使うかは探索担当が資料から選び、開発者は答えを指定しません。

追加する案内は次の一文です。

> 資料内に同じ不足を満たす有力な代案がある場合は、同じ変更枠・共通構築・開始状態からその代案も1件比較し、差を採用配分・用途・枝の継続判断へ戻してください。

「採用配分」は採用枚数や交換枠、「枝の継続判断」は同じ着想を続けるか別の着想へ移るかの判断です。追加指示は本体へ採用せず、分けた実装で検証しました。

## 実施した検証手順

1. 開始前に、比較条件・成功と数えるもの・時間上限を固定しました。
2. 前の試験の検索入口あり側が提出した案を、提出終了時点の保存一覧から復元しました。全30ファイルの一致、正式案1件・評価0件・資料25件を確認。後で作られた別評価の入力は除外しました。新しい初見入力の探索ではなく、同じ保存案からの改訂試験です。
3. 考案指示へ一文だけ加える実装を試作。既存の関連122検査と型検査が成功し、公開入口から実際の入力を読んでも、追加文とその識別値以外が変わらないことを確認しました。別評価・調査引き継ぎの入力は完全一致しました。
4. 両方式を一度ずつ開始し、実際に渡った指示・資料を照合しました。改訂は15分以内、続く別担当の評価は10分以内です。提出済み内容を確認してから次工程へ渡します。追加の自動改訂や時間切れ後のやり直しはしません。
5. 両方式とも正式改訂1件と別評価1件を保存して終了。元入力・旧案・実装・終了明示を再照合して回収し、別担当が公開記録と方法の効果を点検しました。
