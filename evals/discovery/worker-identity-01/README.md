# 別々に起動した担当を実行側の識別値で区別する

**担当の識別不具合を修正し、改訂1件・別担当の正式評価1件・全体報告まで通ったため、実行補助として採用します。** 一度の実行は約12分15秒でした。一方、今回の案は「条件付き成立・追加検討・独自性未確認」で、試行推薦は0件です。実行の成功を案の有用性と分けて記録します。

## 前の失敗と修正

前の[接続試行](../revision-runner-01/README.md)では、改訂担当と評価担当を別々に起動したのに、両方が `/root` と名乗りました。保存処理は文字列だけで担当を区別していたため、同一担当による評価として拒否しました。正式改訂1件・正式評価0件という前の失敗は保持しています。

修正後は、実行ごと・工程ごとに担当IDを割り当てます。正式な改訂・評価を提出する共通の受付を、ここでは「公開入口」と呼びます。外部への公開ではなく、担当が使う操作口です。提出時は担当情報だけをそのIDへ結び、元の申告名と回答本文を公開操作記録へ残します。元の提出ファイルも保持し、判断・手順・根拠は変更しません。公開入口を通さず保存した正式ファイルにも、起動時の担当IDとの一致を求めます。

モデル名や推論設定、通常の考案指示、採否の基準は変更していません。未提出・時間切れ・入力変更・余分な正式提出では停止し、自動再試行や代理提出をしない動作も保ちました。

## どう検証したか

1. [条件](protocol.json)を先に固定しました。前と同じB正式案・正式評価から、改訂20分、別評価15分、各1回で確認します。前の未登録評価を代理提出したり、同じ失敗を成功へ書き換えたりはしません。
2. 同じ名乗り、名乗りの欠落、元回答の保持、同一IDでの自己評価、割当外IDによる直接保存を検査しました。関連する既存処理も含め93件が13.25秒で合格し、型検査にも合格しました。初回の検査では、新しく追加したテスト3件が保存階層を誤って参照して失敗しました。参照箇所を訂正し、再実行で93件すべてが合格しました。[範囲と結果](verification.json)
3. 別担当も5ケースを再現し、正常保存と拒否を確認しました。公開入口は別プロセスで動かしていますが、ここまでは合成回答の検査です。[別点検](independent-code-audit.json)
4. 実AIで、改訂を8分22秒、評価を3分52秒で完了しました。約0.66秒で次の担当へ自動で進み、正式改訂・正式評価を各1件と全体報告を保存しました。公開操作75件に失敗はありませんでした。[実行結果と時刻](live/verification.json)
5. 元探索と主カードDBの保持を照合し、元回答と正式保存の全項目が担当情報以外は一致することを確認しました。実AIは両者とも割当IDを自ら記入しており、同じ `/root` を実行側で結び直す動作は手順2・3の合成回答で確認した範囲です。[担当情報と本文の照合](live/identity-check.json)

## 今回の案の結果

「圧縮を外す再始動ランプ：ノマの処理から絶倒、守護無視へ」は、山札圧縮を見送り、既存の全体処理から攻撃を再開する方針へ変わりました。圧縮用の準備と後続札の消滅を取り除いた点は、説明の言い換えだけではない変更です。

ただし、別評価は通常構築のサガを使う対照を指摘しました。指定した2ターンの比較では、提案12点に対して通常側は10点を出し、相手の守護も処理できます。提案には手札と後続を残す利益がありますが、2点の差と引き換えに守護を残し、回復などの枠も減らしています。その負担を補う決着条件を特定できず、**今回は試す理由のある種に至ったとは判定しません**。[正式評価と次の問い](live/review/review.json)

指定したPP・手札・盤面の手順は条件付きで整合しています。補足の生存例には訂正があり、自体力12から8点を受けた後は、追加3点なら体力1で生存し、追加4点で敗北します。「低コストの札」と「防御を担う札」の数え方も分ける必要があります。これらを元の提出本文へ上書きせず、評価として保持します。

絶倒とアンテマリアの接続自体には保存済みの既存構築があります。ランプの防御後へ少量加える用途の普及は未確認で、今回の担当は外部検索を行っていません。前回と生成内容が違うことを、担当識別の修正による発見力の変化とは主張しません。

## 評価へ渡す情報の限界

評価担当は別プロセスで起動し、旧評価ファイルと古い考案資料は除外しました。しかし、今回の改訂理由に「直前評価のvalue=developを受け」という文章が残っています。**過去の判断を完全に伏せた評価ではありません。** 追加資料だけでなく、提案や履歴の文章にも旧判断が混ざりうることを記録しました。途中でその文章や評価条件を変更していません。[確認した箇所](review-isolation-note.json)

今回採用するのは、工程を順に起動して正式保存を確認する実行補助です。全行動の隔離や本人認証、過去判断を完全に伏せる機能まで確認したものではありません。
