# 先例・普及・資料不足を区別する説明の比較

探索システムの判定指示を変更するかを判断する報告です。**現行・説明明確化とも6件の固定条件に合格し、説明追加の効果は示せませんでした。本採用は保留し、本体の指示は変更していません。**

## 方法と結果

同じ仮想6事例と現行の判断原則全文を、互いの回答を知らない新規実行2件へ渡しました。変更版は独自性の説明だけを2行から5行へ置換しています。期待判定と採否条件は実行前に固定し、担当へ渡していません。外部検索はせず、記載済みの仮想観測を判定する検査です。

| 例 | 確認した境界 | 現行 | 説明明確化 |
|---|---|---|---|
| 1 | 個人先例を認めるが、1件を普及と扱わず未確認を維持。 | 合格 | 合格 |
| 2 | サイト数だけでなく、標準的な役割・配分・手順と大会での使い方の一致を根拠に既知と判断。 | 合格 | 合格 |

総数12回答＝現行6件合格＋説明明確化6件合格。全件で判定値が一致しました。別担当が理由も読み、先例と普及の区別、具体的な不足の保持、調査範囲の限定を確認しました。手順の成立と試用価値も、独自性だけで書き換えていません。

## 採否と次の対応

**本採用保留。** 事前に「現行で観測された誤りを少なくとも1件解消し、他の件に後退がないこと」を採用条件としました。同点なので、説明を増やす根拠は得られていません。1回ずつの短い実行であり、19秒の差を速度の一般的な優劣とは扱いません。

過去の5案の独自性を認定し直す検査ではありません。共通原則に残る「落とす」と「ユーザーが判断する」等の表現の曖昧さも、この結果だけで解消したとは言えません。仮想資料を読む判断と、実際に必要資料を取得して新しい種を生む力は別です。次は、保存した探索経験を別の探索で再利用できるかを点検します。
