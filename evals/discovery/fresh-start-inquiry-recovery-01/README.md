## 方法と手順

1. 前試行の後続工程の登録漏れにより、調査AIは起動前に停止していました。その失敗を保持し、保存済みの案・評価・資料をそのまま引き継ぎました。調査と別照合の両工程が未着手として登録されていることを、公開実行前に既存の台帳機能で確認しました。
2. 条件と入力・実装の識別値を固定しました。調査15分・別照合10分を各一度とし、担当へ個別カードの答え、新たな出典、期待する結論を与えていません。調査AI自体は今回が初回実行です。
3. 調査担当が保存案・カード本文・両側の注記を読み、27検索語と取得内容・解釈・限界を保存しました。カード名の同居、同じ用途の説明、一般的な普及を区別しました。
4. 別担当が13URLを照合しました。中心となる記事の用途説明を再取得し、保存された表セルを再集計しました。動的な表の外部再取得、原投稿、一部の公式本文など取得できなかった対象は、確認済みにしませんでした。
5. 両担当は期限内に正常終了しました。公開操作は調査28回・別照合17回で、公開入口の操作エラーは0件です。外部ページの取得不能がなかったという意味ではありません。
6. 回収時に、各報告ファイルと正式添付、公開入口での全文再読、元の案・評価・DB・固定実装の保持を再確認しました。結果をプロジェクトの保存先へ複製し、全内容の一致を確認しました。追加資料は7件、追加の正式案・正式評価は0件です。

実戦の強さ、必要札が集まる頻度、勝率、初見での有利さは今回の調査対象ではありません。既存の1枠の試用理由は保持しますが、有用な独自の種として新たに確認できた件数は0件です。

## 採否と、仕組みに戻す課題

**案の独自性については保留です。** 基本用途の先例はあるものの、案全体と一般的な普及を確定する根拠がないためです。先例が一つあっただけで案を棄却せず、未発見だけで独自と認定することも避けます。

工程登録を確認してから実行することで、前の起動前失敗は復旧できました。既存の開始・調査・照合・保存の機能を使っており、今回新しい実行機能を採用したわけではありません。

現在の記事を考案へ渡しても、基本用途に先例がある案が残りました。資料の保持だけでは、そこから別の使い方を発展させる効果まで得られたとは言えません。次の[比較試行](../resource-use-01/README.md)では、調査で分かった手順で得られるもの（使えるPPや手札など）の使い先を変え、これまでの案にはない働きができるカードを探します。新しい案は1つだけ比較し、元案も選べるようにします。過去の行動順点検や採用枚数の縮小、今回の別評価が既に見つけた手順の再選択は発展に数えません。次試行の更新時点では、変更版の131検査・型検査と実入力一致を確認し、現行・変更版とも改訂中です。
