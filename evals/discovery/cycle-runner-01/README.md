# 評価後の改訂を一度だけ自動でつなぐ

**実AIは初回の案と別評価を保存し、試用判定で正常停止しました。** 追加改訂は実施していません。正式評価を根拠に継続・停止を管理する実行補助として採用しました。システム全体の完成は未認定です。

[進捗画面で工程と原文を見る](http://127.0.0.1:8765/#experiment/cycle-runner-01)

## 何を変えたか

これまでは、考案と別評価が終わるたびにメイン担当が結果を読み、必要な改訂を別の実行として起動していました。`discovery_cycle` は、正式評価が「追加検討」で次の問いがある場合だけ、保存済み資料から改訂と別評価を一度つなぎます。試用・却下・不明・問いなしでは追加しません。二回目の評価後は必ず止めます。

開始時の実装を固定し、全工程に同じ版を使います。元の入力、各回の正式案・評価・追加資料、継続または停止の根拠と時刻を保持します。考案と評価の指示、判定基準、モデル設定は変更していません。

## 実際の検証手順

1. 継続条件・最大2回・各担当の固定予算を開始前に保存しました。
2. 既存の考案・別評価の入口を組み合わせ、正式保存と元入力の保持を検査してから次へ進む入口を実装しました。
3. 分岐、未提出、失敗、入力変更、履歴保持、同一実装の利用など101件と型検査を確認しました。最初の試験は、試験用の二回目の案が初回と同内容で既存検査に拒否されました。製品の制約は緩めず、試験データへ実変更を入れて再確認しました。さらに実中断時の子処理の終了1件を確認し、計102件を通過しました。
4. 保存DBのエルフ・ローテーション記事4URLを全件選び、全40枚・取得情報・本文の計12資料を取得しました。具体的な過去案・評価やメイン担当のカード答案を追加せず、新しい探索記録を固定しました。
5. 公開コマンドから実AIを実行しました。初回の正式案1件を保存した後、自動で別担当の評価へ移りました。
6. 別評価は「手順支持・比較試用・独自性未確認」でした。次の問い4件をそのまま残し、「試用」判定を理由に停止しました。二回目の2工程は未実施で、開始終了時刻を作っていません。

## 得られた案と評価

初回案は、参考テンポエルフの**導きの船頭3→2、森羽子板の匠0→1**という1枠交換です。既存2枚のシトラスを増やさず、妖精の生成を当ターンの追加打点へ変える案でした。

主比較は、後攻8ターン目、8PP、EP1・SEP0、手札3枚、相手に6/7守護がある状態から同じターン終了までです。共通手札はシトラスとオルテニア、残る1枚を匠／船頭で対応させています。

| 同じ開始状態の行動 | 即時打点 | 終了時に残る主なもの |
|---|---:|---|
| 匠＋シトラス進化 | 5点 | 匠4/4、手札1枚。評価での訂正を採れば妖精1/1も残せる |
| 船頭進化＋シトラス | 0点 | 船頭6/5＋シトラス1/1＋妖精1/1、手札1枚 |
| 共通のオルテニア進化 | 0点 | 本体9/3＋3/3守護3枚、手札2枚、進化回数も多く残る |

どの行動でも相手の守護は除去できます。匠の5点には、通常側が残せる盤面・防御を失う負担があります。主比較は相手体力10→5であり、決着ではありません。

別評価は、通常の序盤運用を維持し、既存の決着札を持てない場合の補助として1枚を比較試用する理由を認めました。一方、共通手札のオルテニアをセタス＆メイシアに替えた別条件なら、通常札1枚・7PP・EP1で守護除去と6点、6/8守護を得られます。匠が通常の決着札より優れるという結論ではありません。

### 元案を保持したまま残す訂正

- 元の匠側の手順は、最後に妖精を1枚余分に突進させています。妖精1枚を残しても、進化シトラスで守護を倒せます。5点・必要PP・手札・除去の成立は変わらず、終了盤面だけ改善します。
- 通常側の前半で「相打ち」と書かれた箇所は、妖精だけが死亡する場面です。双方が死亡するという意味では不正確です。
- 防御を減らして5点を入れる価値、引き込みの頻度、シトラスやEPを温存する損失は未解決です。
- 外部の普及調査は未実施です。参考4構築に入っていないことは独自性の証明ではありません。実戦勝率・Tier・初見での優位も未確認です。

## 確認できたことと限界

- 実AIで、初回の考案→別評価→試用判定での停止→履歴付き結果の保存までを確認しました。
- 次の問いが残っていても、それだけで追加改訂へ進みませんでした。停止理由は対応する正式評価の識別値と一緒に保存されています。
