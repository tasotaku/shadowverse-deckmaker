# 評価後の改訂と再評価を一度の実行でつなぐ

**改訂と独立評価を一度のコマンドでつなぐ入口を実装し、実際の保存案で確認しています。** 機能の検査90件と型検査には合格しました。実AIは2026年9月10日18時10分46秒（日本時間）から改訂中です。実行補助としての採否と、案が良くなったかはまだ未判定です。

前の試行では、親担当が毎回、資料の複製、旧評価の分離、担当の起動、正式な保存結果の回収を個別に行っていました。新しい入口では、この受け渡しを実装にまとめます。考案や採否の基準は従来のままです。

## 何を実装したか

元の探索を固定 → 別の保存先で考案・改訂 → 正式提出と入力保持の確認 → 新しい担当で評価 → 正式評価と報告の回収、を順に行います。

元の記録には書き戻さず、出力先に改訂1件・別評価1件と全体報告を残します。担当が正常終了しただけでは次へ進みません。未提出、時間切れ、入力の書き換え、余分な正式案や評価、不正な判定値を区別して停止します。再試行や代理提出は自動では行いません。

改訂担当には直前の評価と残った問いを渡します。次の評価担当には、現在の案・カード本文・追加資料・改訂履歴を渡し、旧評価ファイルと古い考案資料は渡しません。追加資料の本文へ旧採否を書き写してしまった場合までは機械では判断できないため、その有無は実行結果から別に確認します。

開始終了の時刻と時間制限は、既存の実行監視を使います。進捗記録へ接続した場合、担当の開始・終了を自動反映します。評価の有用性や方式全体の採否は、実行状態から自動決定しません。

## どう検査したか

新規21件と関連する既存69件の合計90件が合格し、12.66秒でした。型検査にも合格しています。

正常な受け渡し、追加資料を保存した後の提出、初回考案と改訂、既存出力の保護、時間制限の不正値、未提出・時間切れ・資料の書き換え・余分な評価・差し替え資料による形式だけの改訂を検査しました。合成回答を使う実プロセスの確認も行いましたが、これを実AIでの完走とは数えていません。[検査範囲と結果](verification.json)を保存しています。

作成中に3つの問題を再現して修正しました。旧資料を除くと改訂履歴も読めなくなる問題、考案担当が追加した親案への評価を見逃す問題、親案を消した資料へ差し替えると題名だけの改訂が通る問題です。別担当も修正後の通常経路と拒否を確認しました。[別点検の記録](independent-code-audit.json)に残しています。

## 実際の案で何を確認するか

前の「経験参照あり・なし」の比較から、経験参照側の正式案と正式評価を使います。山札を圧縮して検索先を絞る利益が、その負担を補うか未解決だった案です。元試行の採点や初回比較は変更しません。

この保存入力から通常の指示で20分以内に1回改訂し、正式提出を確認できた場合だけ、別の担当が15分以内に評価します。親担当が間に資料コピーや起動操作を挟まず、報告の回収まで通るかを測ります。失敗した場合も途中出力と停止理由を残します。

案の評価では、手順の正しさ、元の構築との比較、得た役割と失った役割、核を引かない時の方針、独自性の調査範囲を従来の5基準で確認します。改訂を保存できたことや、計算を直したことだけを有用性の合格にはしません。実行補助の採用と、良い種への到達は別に判定します。[固定した検証条件](protocol.json)に全文があります。
